    Regvue Modern Hardware/Software Interface (HSI) Documentation¶

    원문 보기

    Regvue는 정적 문서(Word/PDF/HTML) 기반 레지스터 문서화의 한계를 해결하기 위해 JSON 기반 RDF 포맷을 입력으로 받아 필드 인코딩/디코딩, 퍼머링크, 다중 리셋 표시 등을 제공하는 웹 기반 레지스터 문서 도구이다.

    항목 내용
    저자/출처 Rob Donnelly, Josh Geden (Jet Propulsion Laboratory, California Institute of Technology)
    유형 PAPER
    카테고리 System-SW
    ID ref-20261018-5ce8

    핵심 인사이트¶

    • RDF JSON은 CMSIS-SVD/IP-XACT의 XML 파싱 부담을 피하고 JSON.parse() 한 번으로 로딩되도록 설계되어, 후처리를 최소화하는 것이 핵심 설계 동기다.
    • RDF 스키마에 버전 정보를 넣어 하위 호환이 깨지는 변경을 허용하면서도 구/신 버전 문서를 동시에 지원할 수 있게 했다.
    • Git 저장소에 RDF JSON을 직접 두면 버전 관리(URL의 Git 버전)와 인증(GitHub 접근 제어)을 무료로 얻지만, 브라우저 Same-Origin/CORS 제약 때문에 Regvue 앱도 같은 GitHub에 호스팅해야 한다는 트레이드오프가 있다.
    • Electron 대신 Tauri를 검토한 이유는 Electron 패키지가 번들된 Chromium 때문에 100MB 이상이 되는 반면, Tauri는 OS 웹뷰를 사용해 1~2 자릿수 더 작게 만들 수 있기 때문이다.
    • 문서는 Regvue가 Europa Clipper 미션에서 실제 사용되었다고 밝히지만, 자동 생성 도구 성능이나 정량적 효과에 대한 수치 평가는 포함하지 않는다.

    상세 요약¶

    배경 및 문제 정의¶

    레지스터 문서는 보통 Word, PDF, 정적 HTML로 작성되는데, 이 형식들은 정적이고 공유가 어렵다. 레지스터 값을 필드로 자동 디코딩하거나, 특정 섹션을 동료와 공유하려면 문서 파일, 섹션 번호, 제목을 모두 전달해야 하며 상대방은 뷰어를 준비해 수동으로 찾아가야 한다. 저자들은 이러한 한계를 해결하기 위해 현대 웹 기술 기반의 풍부한 레지스터 문서 경험을 제공하는 Regvue를 제안한다.

    핵심 아키텍처 및 방법론¶

    입력 포맷 (RDF JSON): 설계별 레지스터 정보는 Regvue 전용으로 만든 Register Description Format(RDF) JSON 파일에서 로드된다. CMSIS-SVD에서 영감을 받았지만 후처리를 최소화하도록 설계되었고, XML 대신 JSON을 쓰므로 DOMParser 없이 JSON.parse() 한 번으로 파싱된다. RDF는 다른 RDF 파일을 include할 수 있어 module → chip → system 순으로 계층적 뷰를 구성할 수 있다.

    스키마 검증: JSON Schema 표준으로 RDF를 기술하며, 필수 속성 누락 등은 검증기가 오류로 보고한다. 스키마에는 버전 정보가 포함되어 있어 호환성이 깨지는 변경을 도입하더라도 두 버전을 동시에 지원할 수 있다.

    웹 애플리케이션 및 기능: - 증분 퍼지 검색: 블록, 레지스터, 필드의 이름, 설명, 오프셋을 대상으로 키보드만으로 검색하며, 최근 선택 항목을 제공한다. - 필드/레지스터 인코딩·디코딩: 필드 값을 입력하면 레지스터 쓰기 값이 실시간 계산되고, 반대로 읽기 값을 붙여 넣으면 필드 값이 나온다. - 바이트 스왑: little endian(설계/검증)과 big endian(소프트웨어) 간 변환을 지원한다. - Enumerated values: 원시 값을 IDLE 같은 심볼릭 값으로 매핑한다. - 다중 진법(B|D|H)과 다중/선택적 리셋: 여러 리셋(예: power-on reset, PCI reset)이 걸린 필드를 표시하며, 선택된 리셋의 영향을 받지 않으면 ?로 표시한다. - 퍼머링크: 블록, 레지스터, 필드에 변하지 않는 직접 링크를 제공한다.

    호스팅: 정적 파일만 배포하면 되므로 GitHub Pages, GitLab Pages, 또는 localhost의 Python 정적 서버로 운영할 수 있다. 하나의 배포로 여러 설계를 서비스할 수 있으며, 사용자는 URL 또는 파일시스템으로 RDF JSON을 로드한다. 파일시스템 로드는 same-origin 정책상 include를 지원하지 않으므로 URL 로드가 권장된다.

    JPL의 호스팅 구성: Regvue 앱은 GitHub Pages에, RDF JSON은 GitHub Enterprise의 Git 저장소에 둔다. 이로써 Git 버전이 URL에 자연스럽게 포함되고 GitHub 접근 제어로 인증이 해결되는 이점이 있다. 대신 Fetch API의 same-origin 제약과 GitHub raw 링크의 CORS 미지원으로 인해 앱도 GitHub에 있어야 한다는 제약이 있다.

    구현 기술: TypeScript(컴파일 타임 타입 검사로 버그를 조기 발견)와 Vue 프레임워크(search, address map, register layout 등을 컴포넌트로 구성)로 구현되었다.

    개발 이력: 원래는 라이브 하드웨어의 레지스터를 파일 탐색기처럼 조작하는 "Register Explorer"로 시작했다. Python/Tk 프로토타입은 레지스터 레이아웃 렌더링에 많은 해킹이 필요했고, HTML 프로토타입이 잘 동작했으며, cefpython으로 임베드했을 때도 동작했지만 3대 OS용 패키징과 지원이 어려웠다. 이에 웹 앱으로 전환하기로 결정했다.

    Europa Clipper 적용: 기존 레지스터 자동화 도구 Register Translator를 확장해 대부분의 FPGA 설계의 RDF JSON을 자동 생성했다. 명세 형식이 맞지 않은 두 FPGA 설계는 ad hoc Python 스크립트를 작성했고, 최상위 Europa Compute Element(ECE)의 RDF JSON은 셸 스크립트로 FPGA 레벨 JSON을 include하여 만들었다.

    향후 과제: 라이브 하드웨어 제어를 위한 데스크톱 앱이 필요하다. Electron은 패키지가 100MB 이상이 되므로, OS 웹뷰를 쓰는 Tauri로 Regvue Desktop 프로토타입을 만들었다. 이 프로토타입은 UART 시리얼 콘솔을 통해 레지스터를 읽고 쓸 수 있으나, 배포 전 해결할 과제가 남아 있다.

    실험 결과 및 결론¶

    이 문서는 정량적 벤치마크나 실험 평가 결과를 제시하지 않는다. 결과로 제시되는 것은 (1) Europa Clipper 미션에서의 실제 사용 사례, (2) 정적 문서 대비 공유·디코딩·버전 관리 측면의 정성적 장점, (3) Tauri 데스크톱 프로토타입의 동작 시연이다. Apache 2.0 및/또는 MIT 라이선스로 NASA-JPL GitHub 조직에서 오픈소스화가 진행 중이라고 밝혔다. 결론적으로 레지스터 정보는 문서이므로 인터랙티브 문서 도구로서 HTML 기반 웹 앱이 적합하다는 설계 판단을 확인했다. 다만 자동 생성 도구의 정확도나 엔지니어링 시간 절감 효과는 본문에서 수치로 검증되지 않았다.
