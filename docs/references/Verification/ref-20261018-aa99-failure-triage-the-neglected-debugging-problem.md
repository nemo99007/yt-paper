# Failure Triage: The Neglected Debugging Problem

[:material-open-in-new: 원문 보기](https://dvcon-proceedings.org/wp-content/uploads/failure-triage-the-neglected-debugging-problem.pdf){ .md-button .md-button--primary target=_blank }

> 회귀 검증에서 쏟아지는 실패들을 root cause analysis 엔진이 추출한 excitation/propagation 경로를 시그니처로 삼아 자동으로 bin에 묶고, 적합한 담당자에게 배정하는 failure triage 프레임워크를 제안하고 FPU·VGA 두 사례로 검증한 논문.

## 핵심 인사이트

- 에러 메시지만으로 실패를 묶으면 같은 checker가 서로 다른 버그를 잡거나(over-grouping), 같은 버그가 다른 checker에 잡히는(under-grouping) 두 방향의 오분류가 생긴다. 메시지 기반 시그니처의 근본 한계다.
- RCA 엔진이 주는 신호 전파 경로와 activation time을 시그니처로 쓰면 checker 관측 정보보다 설계 내부 동작을 반영해, 체커를 과도하게 추가하지 않고도 버그 소스를 구분할 수 있다는 것이 핵심 아이디어다.
- binning은 경로 유사도 점수 + clustering threshold 구조이며, 모드·변경 이력(source control)·stimulus 정보를 가중치나 tie-breaker로 쓸 수 있다. 실제 임계값은 환경별 실험으로 튜닝해야 한다.
- 담당자 배정 측면에서는 bin별 최빈 모듈의 owner나 마지막 커밋 작성자를 활용하는 방식을 제시한다. 이는 '잘못된 사람에게 넘기며 시간 낭비'를 줄이는 실무적 가치와 연결된다.
- 논문 스스로 한계를 인정한다: 서로 가까이 있는 distinct 버그는 같은 bin으로 묶일 수 있고, 평가는 두 개의 작은 사례 연구(FPU 5 bin, VGA 4 bin)에 기반하므로 정량적 일반화에는 제약이 있다. 또한 '더 높은 정확도'라는 주장의 정량 비교 수치는 본문에 제시되지 않는다.

## 상세 요약

### 배경 및 문제 정의

기능 검증에서 디버그는 전체 검증 시간의 최대 50%를 차지한다고 인용된다(Foster [1]). 본 논문은 디버그 중 상대적으로 주목받지 못한 **Failure Triage**, 즉 야간 회귀 테스트에서 발생한 대량의 실패를 근본 원인(root cause)이 같을 가능성에 따라 묶고(binning), 그 버그의 담당자(owner)에게 배정하는 초기 단계에 초점을 맞춘다.

저자들이 지적하는 현재 실무의 두 가지 접근은 다음과 같다.
- **수작업(gut feel)**: 전담 엔지니어가 매일 실패를 분석해 담당자를 찾는다. 정확하지만 느리고 지식에 의존한다.
- **스크립트 자동화**: 에러 메시지와 테스트 owner 기준으로 bin을 만든다. 빠르지만 부정확하다.

핵심 문제는 에러 메시지가 실패의 **시그니처로서 정보가 부족**하다는 점이다. 같은 checker가 서로 다른 버그를 잡을 수 있고(Figure 1), 같은 버그가 stimulus에 따라 다른 checker에 잡힐 수 있다(Figure 2). 담당자 배정이 잘못되면 엔지니어 간 핑퐁이 일어나 시간이 낭비된다.

### 핵심 아키텍처 및 방법론

전체 흐름은 다음과 같다.

```mermaid
flowchart LR
    A[Nightly Regression Tests] --> B[Multiple Failures]
    B --> C[Automated Root Cause Analysis Engine]
    C --> D[Failure Signatures<br/>excitation/propagation paths]
    D --> E[Failure Binning Engine]
    E --> F[Bin 1 ... Bin N]
    F --> G[Owner 배정]
```

1. **Signature 생성**: RCA 엔진(OnPoint, critical path tracing [2], SAT/QBF/SMT 기반 기법 [2,3])을 블랙박스로 사용해 실패별 전파 경로와 회로 요소 집합을 얻는다. 상용 도구는 수정에 필요한 값의 waveform과 "activation time"도 제공한다. 여기에 사용자 메시지(상태 머신 trace 등), source control 변경 이력, stimulus/모드 정보를 보강할 수 있다.

2. **Binning**: 경로를 activation time 기준 시간순으로 정렬해 error path의 proxy를 만들고, 두 경로의 공통성에 따라 유사도 점수를 계산한다. 점수가 높으면 같은 bin, 낮으면 분리한다. 최근 변경 코드는 필터 또는 가중치로, 운영 모드는 tie-breaker로 쓸 수 있다. 임계값(threshold)은 환경에 따라 조정 가능한 파라미터다.

3. **담당자 배정**: bin 내 최빈 모듈의 owner 또는 해당 bin의 마지막 커밋 작성자를 source control DB에서 찾는다.

논문은 이 방법이 상용 도구로 구현되어 있고 통신 응용 상업 설계에 적용되었다고 밝히지만, 세부 데이터는 기밀로 공개하지 않는다.

### 실험 결과 및 결론

평가는 Toronto 대학원생과 협업한 두 개의 샘플 설계에 대한 **정성적 사례 연구**다.

- **Design 1 – FPU (Opencores 기반 single precision IEEE 754, Verilog 8개 모듈 1,415 LOC)**: 실패를 **5개 bin**으로 묶었다. 메시지만 썼다면 4개 bin이 되어 최소 2개 버그 소스가 식별되지 못하고 1개 bin에서 중복 에러가 발생했을 것이라고 주장한다. 발견된 버그는 누락된 pipeline stage, testbench의 잘못된 stimulus, 잘못 설정된 상위 비트, case문의 잘못된 신호 디코딩, 예외 처리 reference model의 오류 등으로 DUT 밖의 버그도 포함된다.

- **Design 2 – VGA controller (Opencores 기반, Verilog 17개 모듈 4,076 LOC, 약 90K gate, UVM 테스트벤치, SVA 50개)**: 메시지 기반이면 6개 bin이 되지만 실제 에러는 4개이며, 제안 방식은 **4개 bin**을 정확히 생성했다고 보고한다. 버그는 색상 처리 상태 머신의 잘못된 할당, FIFO read pointer의 잘못된 비트/함수 사용, testbench의 잘못된 모델 인스턴스, reference model 오류 등이다. 검증 방법은 해당 bin의 버그를 수정하면 그 bin의 모든 실패가 사라지는지 확인하는 것이다.

**결론**: 저자들은 RCA 경로 기반 시그니처가 메시지 기반이나 스크립트 방식보다 낫고 자동화가 가능하다고 결론짓는다. 다만 (1) 사례가 두 개뿐이고, (2) 가까운 distinct 버그가 같은 bin으로 묶일 수 있으며, (3) 정량적 정확도/시간 절감 수치는 본문에 제시되지 않는다는 점을 고려해 해석해야 한다. 향후 과제는 binning 해상도 개선과 testbench/환경 기인 버그를 위한 맞춤형 휴리스틱이다.
