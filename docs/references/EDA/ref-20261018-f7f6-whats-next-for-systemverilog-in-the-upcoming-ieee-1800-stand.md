# What's Next for SystemVerilog in the Upcoming IEEE 1800 standard

## 핵심 인사이트

- covergroup 상속(Mantis 4703)은 검증 IP 베이스 클래스 라이브러리 확장에서 가장 많이 요청된 기능으로, 베이스 coverpoint 교체·제외와 확장 클래스에서의 cross 추가를 가능하게 합니다.
- 벤더별로 이미 구현된 확장 기능(예: constant expression에서 $sformatf 사용, method chaining)이 LRM에 명세되지 않아 사용자가 도구마다 직접 테스트해야 하는 상황이 표준화의 직접적 동기입니다.
- real 타입의 constraint/covergroup 지원은 weight 분포(:/ vs :=)와 real_interval 옵션처럼 이산 값 중심 설계를 실수 범위로 확장하는 새로운 의미 정의가 필요함을 보여줍니다.
- static ref 인자(Mantis 2583)는 automatic 변수에 대한 nonblocking assignment, force, fork-join_any 참조 제약을 우회하기 위해 static 한정자를 도입하는 방식으로, 인자 수명에 대한 명시적 계약을 만듭니다.
- P1800-2023은 아직 승인된 IEEE 표준이 아니며 본문의 모든 기능은 최종 IEEE 투표 전이므로 실제 도구 도입 전 최종본 확인이 필요합니다.

## 상세 요약

### 배경 및 문제 정의

SystemVerilog LRM은 2017년 IEEE 1800-2017로 마무리된 이후, 도구 벤더들이 고객 요구에 따라 자체 확장 기능을 추가해 왔습니다. 그 결과 사용자는 문서화되지 않았거나 불완전한 기능들이 뒤섞인 상황에 놓였고, 어떤 기능이 어느 도구에서 지원되는지 직접 시도해 보기 전에는 알 수 없습니다. 예를 들어 LRM은 constant expression에서 `$sformatf` 같은 built-in 함수 사용을 명시적으로 허용하지 않지만, 일부 도구는 이를 허용합니다. 이에 따라 일부 사용자는 Chisel, Perl, Python 등 다른 언어를 병행하거나 우회 코드 패키지를 만들고 있습니다.

P1800 프로젝트는 2019년 말 시작되었으며, 팬데믹으로 약 2년이 지연된 뒤 end user와 벤더로 구성된 Working Group이 Mantis 이슈 트래커를 통해 이슈를 접수하고 있습니다. 이슈는 다음 세 범주로 분류됩니다.

- **Enhancements**: 언어 기능 확장 (다른 언어에서 차용한 경우가 많음)
- **Errata**: LRM 내부의 명백한 오류 및 모순
- **Clarifications**: 모호하거나 누락된 설명

본문 집필 시점 기준으로 승인된 항목은 Enhancement 26건, Errata 109건, Clarification 61건입니다. 범주는 상호 배타적이지 않으며, 하나의 Enhancement가 Errata나 Clarification을 드러내는 경우가 많습니다.

### 핵심 아키텍처 및 방법론

본 논문은 전체 변경 항목 중 대표적인 사례를 골라 설명합니다. 이 글은 설계 아키텍처가 아니라 표준 개정 프로세스와 언어 기능 명세를 다루므로, 주요 항목을 범주별로 정리하면 다음과 같습니다.

**Enhancements**

1. **Covergroup 확장 (Mantis 4703)**: 클래스 상속처럼 `covergroup extends g1;` 문법으로 기존 covergroup을 확장합니다. 확장 클래스에서 베이스 coverpoint의 bin을 교체하거나 제거하고, 베이스의 coverpoint와 새 coverpoint를 cross할 수 있습니다.
2. **배열 map() 메서드 (Mantis 7610)**: Python에서 차용한 방식으로, 각 원소를 캐스팅하거나 연산한 새 배열을 반환합니다. `item`, `item.index` 암시 변수를 사용하며 `with()` 표현식으로 동작합니다.
3. **`ifdef` 불리언 조합 (Mantis 1084)**: 기존에는 중첩 `ifdef`나 중간 매크로 정의가 필요했으나, `` `ifdef (A && B) `` 형태의 불리언 식을 허용합니다. 값이 아니라 정의 여부만 검사합니다.
4. **멀티라인 문자열 (Mantis 7308)**: `"""` 삼중 따옴표로 여러 줄 문자열을 작성하며, 내부에 단일/이중 따옴표를 포함할 수 있고 삼중 따옴표로만 종료됩니다. 관련하여 text macro 내 멀티라인(1397), 특수문자(1507), printable 문자(7562) 이슈와 얽혀 있습니다.
5. **실수(real) 모델링 (Mantis 7295, 7669)**: random 변수와 constraint에서 real 타입을 허용합니다. 실수 범위에는 `:=` 분포를 쓸 수 없는데, 무한한 이산 값이 존재하기 때문입니다. Covergroup에서는 `type_option.real_interval`로 실수 범위를 겹치지 않는 bin으로 분할합니다.
6. **메서드 체이닝 (Mantis 2735)**: 함수 반환값을 중간 변수로 사용해 멤버를 선택합니다. 하위 호환성을 위해 static 변수 계층 참조(`F.member`)와 구분하려면 `F().member`처럼 인자가 없어도 괄호를 붙여야 합니다.
7. **Static ref 인자 (Mantis 2583)**: `ref static logic arg`처럼 formal ref 인자에 `static` 한정자를 붙여, 실제 인자가 static 수명을 가짐을 보장합니다. 이를 통해 automatic 변수에 대해 금지된 nonblocking assignment, force, fork-join_any 내부 참조 등을 static 인자에 대해서는 허용할 수 있습니다.

**Errata**

- **Clocking block 이벤트 (Mantis 7172)**: `@(dram)`이 `@(posedge phi1)`과 동일하다는 기존 설명은 Active 영역과 Observed 영역의 시점 차이 때문에 모순이었으며, 예제를 수정해 두 이벤트의 실행 시점 차이를 명확히 했습니다.
- **Constraint의 non-integral 함수 인자 (Mantis 2841)**: LRM은 constraint가 integral 타입만 허용한다고 명시하지만, constraint guard에서는 이미 객체 핸들을 허용하고 있었습니다. 이제 `randvar < int'(threshold)`처럼 real 변수에 대한 캐스팅을 constraint 안에서 직접 쓸 수 있습니다.

**Clarifications**

- **컴파일러 지시자 위치 (Mantis 1014)**: `` `ifdef NAME text `endif `` 같이 지시자가 한 줄을 단독으로 차지하지 않아도 되는 구조를 명확히 했습니다. 대부분의 도구가 이미 지원하고 있었습니다.
- **"blocking statement" 정의 (Mantis 225)**: 세 용어 "blocking statement", "non-blocking assignment", "blocking assignment"를 정의했습니다. 예를 들어 `A <= #1 2;`는 non-blocking assignment이지만 blocking statement는 아닙니다. 반면 `A = #4 5;`는 blocking assignment이면서 blocking statement입니다.
- **Packed array 축약 표기 (Mantis 325)**: `int A[100];`처럼 unpacked 배열에만 있는 단일 숫자 축약 문법을 packed 배열(`bit [8] v`)에도 적용하려는 제안이 있었으나, 혼동 가능성 때문에 기각되었고 축약은 unpacked 배열에만 적용된다고 명확히 했습니다.

### 실험 결과 및 결론

본 논문은 실험이나 벤치마크 결과를 포함하지 않습니다. 대신 표준화 프로세스의 현황과 결론을 제시합니다.

- SystemVerilog LRM은 2017년 이후 Working Group을 통해 Enhancement, Errata, Clarification을 체계적으로 정리하고 있습니다.
- 도구 간 불일치를 해소하고 사용자에게 안정성을 제공하는 것이 주요 목표입니다.
- 논문 작성 시점에서 P1800-2023은 아직 공식 승인되지 않았으며, 소개된 모든 기능은 최종 IEEE 투표 승인을 거쳐야 합니다.
- 일부 제안(예: packed 배열 축약 문법)은 혼동을 이유로 기각되었으며, 많은 이슈는 다른 기능에 의해 이미 해결되었거나 범위 밖으로 판정되어 변경되지 않았습니다.
