# Enabling True System-Level, Mixed-Signal Emulation

[:material-open-in-new: 원문 보기](https://dvcon-proceedings.org/wp-content/uploads/157-Enabling-True-System-Level-Mixed-Signal-Emulation.pdf){ .md-button .md-button--primary target=_blank }

> SystemVerilog 실수형 행동 모델(RNM)을 컴파일러 확장으로 에뮬레이터에 직접 합성해, 아날로그/혼합신호 블록을 포함한 SoC를 소프트웨어와 함께 사전 실리콘 검증하는 방법을 제시한 논문.

## 핵심 인사이트

- 기존 에뮬레이션은 synthesizable 디지털 로직만 지원하고, fixed-point 변환은 정확도와 모델 크기 트레이드오프 및 재코딩 비용 때문에 실용성이 낮았음. 이 논문은 RNM을 재작성하지 않고 그대로 합성하는 것을 목표로 함.
- 컴파일러는 real/shortreal/realtime, SV-2012 nettype과 resolution function, #delay, 부동소수점 연산, 일부 수학 함수 등을 지원하지만, 동적 배열, 실수형에 대한 assertion/coverage, real 타입의 force/release, 역삼각함수($atan, $asin, $acos 등), $sin/$cos 입력 범위(±40π) 등에는 제약이 있음. 실무 적용 시 코딩 가이드라인 준수가 필수.
- Bias generator 사례에서 FPU 기반 floating-point RNM을 쓰면 최대 주파수가 959kHz에서 635kHz로 33% 떨어졌지만, 시뮬레이션 14400s 대비 에뮬레이션 45s로 약 320배 속도 향상을 보고. 이 수치는 단일 케이스 기준이므로 일반화에는 주의가 필요.
- 모델 자원 분류(라이브러리 컴포넌트 / 추출 LUT / 최소한의 수작업 SV)와 `ifdef 기반 시뮬레이션·에뮬레이션 분기, 전원 체크 비활성화, VPI+Python 기반 커넥션 추적 같은 실무 기법이 재사용 가능한 방법론으로 제시됨.
- 아크탄젠트 등 에뮬레이터가 직접 지원하지 않는 함수는 사용자 코드 근사로 대체해 A-PLL 위상 검출 루프를 구현. 다만 논문은 정확도를 정성적 파형 비교 위주로 제시해 정량적 오차 분석은 부족함.

## 상세 요약

### 배경 및 문제 정의

현대 SoC는 센서, 고속 데이터 컨버터, 레귤레이터 등 혼합신호(AMS) 블록을 점점 더 많이 포함하지만, 기존 하드웨어 에뮬레이션은 합성 가능한 디지털 로직만 지원합니다. 그 결과 소프트웨어가 아날로그 설정 레지스터를 거쳐 원시 하드웨어 요소까지 제어하는 경로, 아날로그 피드백을 포함한 calibration 루프, 저전력 기법 등은 tapeout 전에 충분히 검증되지 못합니다.

기존 대안들의 한계는 다음과 같습니다.

- **진짜 AMS 시뮬레이션(디지털/아날로그 시뮬레이터 동기화)**: 아날로그 시뮬레이터 런타임 때문에 실행 가능한 테스트 수가 제한됩니다.
- **FPGA 기반 에뮬레이션, 하이브리드 시뮬레이션/에뮬레이션**: 에뮬레이션 처리량이나 용량에 큰 손실이 있습니다.
- **Fixed-point 비트 모델 변환**: 비트 수가 늘수록 정확도는 올라가지만 모델 크기와 라우팅/컴파일 시간이 증가합니다. 논문 II장의 Image Sensor 사례에서는 5.6초의 실제 시스템 동작을 2.1시간의 에뮬레이션 시간으로 검증했지만, 모델 재코딩에 수개월이 걸렸고 시뮬레이션 모델과의 동기화 및 검증 비용이 컸습니다.

따라서 저자들은 SystemVerilog Real Number Modeling(RNM) 및 DMS 검증 방법론을 바꾸지 않고, 기존 RNM을 그대로 에뮬레이션에 합성하는 것을 목표로 합니다.

### 핵심 아키텍처 및 방법론

접근법은 세 층으로 구성됩니다. (1) RNM 코딩 가이드라인 개선, (2) 프런트엔드 컴파일러(ixcom) 확장, (3) 실제 설계를 통한 검증입니다. 컴파일러 출력은 여전히 하드웨어의 compute element에 매핑되므로, 동적 배열이나 루프 한계 같은 행동 언어 기능은 제한됩니다.

**지원 범위 요약**

| 분류 | 지원 | 제한/미지원 |
|---|---|---|
| 데이터 타입 | real, shortreal, realtime, unpacked 배열/struct, SV-2012 nettype, resolution function | resolution function은 합성 가능해야 하며 동적 배열 사용 불가 |
| 지연 | `#` 지연이 있는 always/assign, 이벤트 제어 혼합, rise/fall 게이트 지연 | 일반적으로 비합성인 `#`을 이 방법론에서 허용 |
| 연산 | real 피연산자 연산자(inside 제외), 대부분의 real 수학 함수, $rtoi/$itor/$realtobits 등 변환 함수 | $sin/$cos 입력은 ±40π 이내, $atan/$asin/$acos 미지원 |
| DMS 연결 | 데이터타입 coercion 상당 부분 지원 | CM(Connect Module) 자동 삽입 미지원, 시뮬레이터와 1:1 일치하지 않음 |
| 기타 | - | 동적 배열, real 타입 대상 concurrent/immediate assertion 및 coverage, real의 force/release 미지원 |

**DMS 연결 검증 흐름**

```mermaid
flowchart LR
    A[Top-level IO] --> B[VPI: 계층별 high/low 연결 덤프]
    B --> C[Python 후처리: 신호 경로 조립]
    C --> D[신호 타입 식별: logic / interconnect / coerced wreal / real / custom nettype]
    D --> E[Excel 리포트: 에뮬레이션 빌드 문제 구간 표시]
```

**Bias generator 사례 (SoC 검증)**

- 모델 자원은 세 범주로 나뉩니다. Category 1은 여러 시뮬레이터에서 동작하는 Analog Devices 라이브러리 컴포넌트(전압원, 비교기, AND/OR 등)로, 에뮬레이션 호환 subset을 업데이트했습니다. Category 2는 추출된 LUT로, 기존 프로젝트에서 검증된 내부 도구가 생성한 SV를 수정 없이 사용했습니다. Category 3은 `ifdef 분기 등 꼭 필요한 경우에만 쓴 수작업 SV입니다.
- 기존 환경은 ixcom의 `-moduleStubList` 옵션으로 analog_top을 black box 처리했는데, 이 목록에서 analog_top을 제거하고 bias generator 두 인스턴스만 선택적으로 인스턴스화하는 netlist 구성 뷰를 만들었습니다.
- 에뮬레이션 환경은 원래 전원을 모델링하지 않아 공급 핀이 0으로 고정됩니다. 따라서 전원 체크 로직은 `ifdef로 비활성화하고, 체크 입력은 logic 타입으로 변환해 coercion 문제를 피했습니다.

**A-PLL 사례**

에뮬레이터가 atan을 직접 지원하지 않으므로, 위상 차이 계산을 위해 사용자 코드로 아크탄젠트 근사 구현을 작성했습니다. 기준 신호와 로컬 오실레이터 간 위상 검출 및 보정 피드백 루프를 구성했습니다.

### 실험 결과 및 결론

**CP-PLL**: 기본 charge-pump PLL로 RNM 합성 가능성, 가이드라인, 도구 개선 필요 사항을 검증했습니다.

**4T4R ORAN 트랜시버 SoC (Ubuntu 구동)**: bias generator의 self-trim 루틴(레지스터 쓰기로 시작되는 소프트웨어-디지털-아날로그 상호작용)을 시뮬레이션과 에뮬레이션에서 실행했습니다. 두 환경 모두 trim 루틴이 성공적으로 완료되었고, 파형 차이는 제약 랜덤화 solver 출력 차이에서 비롯됩니다.

| 항목 | 값 (문서 기재 기준) |
|---|---|
| 최대 동작 주파수 | 959kHz (all-digital bias) → 635kHz (full RNM), 33% 감소 |
| 실행 시간 | 시뮬레이션 14400s vs 에뮬레이션 45s, 약 320배 |
| FPU 활용률 | 52.47% |

저자들은 주파수 손실을 floating-point 정확도 확보의 합리적 비용으로 판단했으며, 더 복잡한 케이스에서 속도 향상은 더 커질 것으로 예상한다고 밝혔습니다.

**A-PLL**: 근사 arctan 기반 위상 검출 루프가 에뮬레이션에서 기준 신호에 록(lock)되는 동작을 보였고, Xcelium 기준 시뮬레이션과 파형이 유사하다고 보고했습니다.

**결론 및 한계**

- 저자들은 트랜시버 사례를 근거로 "production ready"라고 주장하지만, 검증 대상은 단일 SoC 중심이고 정확도 평가는 주로 파형 비교 등 정성적 방식입니다.
- 속도 향상 수치도 bias generator 한 케이스에 해당하므로 일반화에는 추가 데이터가 필요합니다.
- 향후 계획으로는 Analog Devices가 시뮬레이션 라이브러리를 에뮬레이션 호환으로 확장하고, Cadence가 도구와 하드웨어에서 추가 RNM/DMS 구문을 지원할 예정입니다.
- 전체적으로 시뮬레이션과 에뮬레이션이 단일 RNM 코드베이스를 공유할 수 있게 되어, 엔지니어가 전체 시스템 검증에 더 많은 시간을 쓸 수 있다는 점이 핵심 가치로 제시됩니다.
