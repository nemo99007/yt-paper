## Summary

<div class="bi" markdown>
<div class="bi-en" markdown>

**Encodes unstructured-pruned, quantized weights as fixed-rate XOR-gate-network seeds solved via GF(2) linear equations, with small patch data for losslessness, giving a regular, parallel-decodable format at roughly 1/(1−S) compression.**

</div>
<div class="bi-ko" markdown>

**비구조적 가지치기와 양자화된 가중치를 GF(2) 선형 방정식으로 푼 XOR-gate network 시드로 인코딩하고, 무손실을 위한 소량의 patch 데이터를 더해 고정 비율로 병렬 디코딩 가능한 정규 포맷(압축률 약 1/(1−S))을 만드는 방법.**

</div>
</div>

## Key Insights

<div class="bi" markdown>
<div class="bi-en" markdown>

- Fixed-rate XOR-gate decoding removes pruned-bit irregularity, so every row decodes in one step and avoids the CSR load-imbalance that limits sparse-matrix speedups.

</div>
<div class="bi-ko" markdown>

- 고정 비율 XOR-gate 디코딩은 가지치기된 비트의 불규칙성을 없애 각 행을 한 단계에 디코딩하므로, 희소 행렬 가속을 제한하는 CSR의 부하 불균형을 피한다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Compression ratio approaches 1/(1−S) because don't-care (pruned) bits are absorbed by solving linear equations over GF(2); higher pruning rates yield higher compression.

</div>
<div class="bi-ko" markdown>

- 가지치기된(don't-care) 비트를 GF(2) 상의 선형 방정식 풀이로 흡수하므로 압축률은 1/(1−S)에 근접하며, 가지치기율이 높을수록 압축률이 커진다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- AlexNet FC5/FC6 at 91% pruning and 1-bit quantization need only 0.28 bits/weight, versus 2 bits/weight for ternary quantization.

</div>
<div class="bi-ko" markdown>

- 91% 가지치기와 1-bit 양자화를 적용한 AlexNet FC5/FC6은 가중치당 0.28비트만 필요하며, 이는 ternary 양자화의 2비트와 비교된다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Lossless reconstruction is obtained with extra npatch/dpatch bits, requiring no retraining; the patch-search heuristic has O(nout) complexity and yields up to 10% more replacements than exhaustive search.

</div>
<div class="bi-ko" markdown>

- 추가 npatch/dpatch 비트로 무손실 복원을 얻으며 재학습이 필요 없고, patch 탐색 휴리스틱은 O(nout) 복잡도로 완전 탐색보다 최대 10% 더 많은 치환을 만든다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Patch-data FIFO banks (nFIFO) bound execution-time variation; the paper reports fewer stalls than CSR as nFIFO grows, but only as relative execution-time plots.

</div>
<div class="bi-ko" markdown>

- Patch 데이터 FIFO 뱅크(nFIFO)는 실행 시간 변동을 제한하며, 논문은 nFIFO가 커질수록 CSR 대비 stall이 줄어든다고 보고하나 상대 실행 시간 그래프로만 제시한다.

</div>

## Detailed Summary

### Background and Problem

<div class="bi" markdown>
<div class="bi-en" markdown>

- Unstructured fine-grained pruning gives high sparsity, but CSR-style indices cause irregular memory access and load imbalance (row-wise sparsity differs), so speedups fail on GPUs (Fig. 1: CSR SpMM on V100).

</div>
<div class="bi-ko" markdown>

- 비구조적 세밀 가지치기는 높은 희소도를 주지만, CSR 계열 인덱스는 불규칙한 메모리 접근과 행 간 부하 불균형을 일으켜 GPU에서 속도 향상이 제한됨 (Fig. 1: V100의 CSR SpMM).

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Structured/block pruning restores regularity but yields lower pruning rates.

</div>
<div class="bi-ko" markdown>

- 구조적/블록 가지치기는 규칙성을 주지만 가지치기율이 낮음.

</div>
</div>

### Architecture and Methodology

<div class="bi" markdown>
<div class="bi-en" markdown>

- Binary quantized weight planes are flattened and split into $n_{out}$-length chunks; each chunk's care bits are matched by solving $\hat{M}_\oplus w_c = w_q$ over GF(2), with $M_\oplus \in \{0,1\}^{n_{out}\times n_{in}}$ a fixed XOR network.

</div>
<div class="bi-ko" markdown>

- 이진 양자화된 가중치 평면을 평탄화한 뒤 $n_{out}$ 길이 청크로 나누고, 각 청크의 care bit을 GF(2) 상의 $\hat{M}_\oplus w_c = w_q$ 선형 방정식으로 맞춤. $M_\oplus \in \{0,1\}^{n_{out}\times n_{in}}$은 고정된 XOR 네트워크.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Equations for don't-care bits are dropped; RREF checks solvability, and any unsolvable care bit is turned into a don't-care and recorded as a patch (npatch count, dpatch locations).

</div>
<div class="bi-ko" markdown>

- don't-care 비트에 해당하는 방정식은 제외하고, RREF로 풀이 가능성을 확인하며, 풀리지 않는 care bit은 don't-care로 바꾸고 patch(npatch 개수, dpatch 위치)로 기록.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Compression ratio $r = mn / (\text{seed bits} + \text{patch bits})$; expected ratio is $n_{out}/n_{in} \approx 1/(1-S)$.

</div>
<div class="bi-ko" markdown>

- 압축률 $r = mn / (\text{seed bits} + \text{patch bits})$; 기대 압축률은 $n_{out}/n_{in} \approx 1/(1-S)$.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Decoding is a fixed-rate XOR network with multi-bank patch FIFOs to absorb patch-induced stalls.

</div>
<div class="bi-ko" markdown>

- 추론 시에는 고정 비율 XOR 디코더와, patch로 인한 stall을 흡수하는 다중 뱅크 patch FIFO를 사용.

</div>
</div>

```mermaid
flowchart LR
  A[Pruned + quantized W] --> B[Flatten and slice to n_out]
  B --> C[Solve M·w_c = w_q on care bits]
  C --> D[Seed w_c + npatch/dpatch]
  D --> E[XOR decoder at inference]
  E --> F[Patch flip to restore care bits]
```

### Results and Conclusions

<div class="bi" markdown>
<div class="bi-en" markdown>

- Bits per weight (Fig. 10): LeNet-5 FC1 (S=95%) 0.19; AlexNet FC5/6 (S=91%, 1-bit) 0.28; ResNet32 (S=70%, 2-bit) 1.22; LSTM PTB (S=60%, 2-bit) 1.67. The paper states an extra 2–11× memory reduction.

</div>
<div class="bi-ko" markdown>

- 가중치당 비트 수(Fig. 10): LeNet-5 FC1 (S=95%) 0.19; AlexNet FC5/6 (S=91%, 1-bit) 0.28; ResNet32 (S=70%, 2-bit) 1.22; LSTM PTB (S=60%, 2-bit) 1.67. 논문은 추가로 2–11배 메모리 감소를 주장.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Accuracy is preserved via patches without retraining; reported ResNet32 accuracy is 91.6% after retraining (baseline 92.5%).

</div>
<div class="bi-ko" markdown>

- Patch로 정확도를 보존하며 재학습은 불필요하다고 함. ResNet32는 재학습 후 91.6% (기준 92.5%).

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Limits: evaluation is algorithmic (bits/weight, relative execution time); no silicon or end-to-end accelerator results are shown, and exhaustive patch search is practical only for nin below about 30.

</div>
<div class="bi-ko" markdown>

- 한계: 평가는 알고리즘 수준(비트/가중치, 상대 실행 시간)이며 실리콘이나 종단 간 가속기 결과는 없음. 완전 탐색 기반 patch 최소화는 nin이 약 30 미만일 때 실용적.

</div>
</div>
