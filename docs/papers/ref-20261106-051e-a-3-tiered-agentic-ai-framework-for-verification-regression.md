## Summary

<div class="bi" markdown>
<div class="bi-en" markdown>

**Proposes a user/block/central 3-tier agentic regression framework, coordinated by pub-sub bridge agents over RabbitMQ with block-level gating before chip-level runs, and reports preliminary industrial evidence from Samsung SoC verification.**

</div>
<div class="bi-ko" markdown>

**사용자, 블록, 중앙의 3계층 agentic 회귀 프레임워크를 제안한다. 이 구조는 RabbitMQ 기반 pub-sub bridge agent로 조율되며, chip-level 실행 전에 block-level 게이팅을 적용한다. Samsung SoC 검증 환경에서의 예비 산업 적용 결과를 함께 보고한다.**

## Key Insights

<div class="bi" markdown>
<div class="bi-en" markdown>

- Scoping regression by design-change locality and verification maturity, with chip-level runs gated on block pass rates (design target 90–95%; 80% used in the evaluation), is the paper's core idea.

</div>
<div class="bi-ko" markdown>

- 회귀 범위를 설계 변경의 국소성과 검증 성숙도에 맞추고, chip-level 실행을 block pass rate로 게이팅하는 것이 이 논문의 핵심 아이디어다(설계 목표 90–95%, 평가에는 80% 사용).

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Before tiering, 2,892 of 20,766 block-level test cases (13.93%) across 33 blocks had no execution record when chip-level regression started, exposing a hidden coverage gap.

</div>
<div class="bi-ko" markdown>

- 계층화 이전에는 33개 block에서 20,766개 block 테스트 중 2,892개(13.93%)가 chip-level 회귀 시작 시점까지 실행 기록이 없어, 숨은 커버리지 공백이 드러났다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Tier decoupling uses RabbitMQ topic exchanges with acknowledgment-based retries; the polling-based fallback without a bridge (A2) was described as adding latency and maintenance cost.

</div>
<div class="bi-ko" markdown>

- Tier 간 분리는 RabbitMQ topic exchange와 acknowledgment 기반 재시도로 구현되며, bridge 없이 polling에 의존한 구성(A2)은 지연과 유지보수 비용을 늘린 것으로 기술되었다.

</div>

<div class="bi" markdown>

<div class="bi-ko" markdown>

## Detailed Summary

### Background and Problem

<div class="bi" markdown>
<div class="bi-en" markdown>

- Monolithic regression re-runs large test sets without regard to design hierarchy or change locality, causing high latency, weak scalability, and redundant debugging. Prior work (Jenkins CI, ML-based triage, LLM log analysis) optimizes single stages only.

</div>
<div class="bi-ko" markdown>

- 단일체(monolithic) 회귀는 설계 계층이나 변경 국소성을 고려하지 않고 대규모 테스트 세트를 반복 실행하여, 높은 지연, 낮은 확장성, 중복 디버그를 초래한다. 기존 연구(Jenkins CI, ML 기반 triage, LLM 로그 분석)는 개별 단계만 최적화한다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Measured gap: before chip-level regression, 2,892 of 20,766 block test cases (13.93%) across 33 blocks were never executed, and some chip runs started at a combined block pass rate of about 23.6%.

</div>
<div class="bi-ko" markdown>

- 측정된 공백: chip-level 회귀 시작 전, 33개 block의 block 테스트 20,766건 중 2,892건(13.93%)이 한 번도 실행되지 않았고, 일부 chip 회귀는 합산 block pass rate 약 23.6%에서 시작되었다.

</div>
</div>

### Architecture and Methodology

<div class="bi" markdown>
<div class="bi-en" markdown>

- Three tiers: user (per-engineer sanity regression, optimized for fast turnaround), block (change-aware, design-aware, and randomized block regression driven by release notes), and central (full-chip regression with error classification and ownership routing to JIRA).

</div>
<div class="bi-ko" markdown>

- 3계층: user(엔지니어별 sanity 회귀, 빠른 피드백에 최적화), block(릴리스 노트 기반의 변경 인식, 설계 인식, 랜덤 block 회귀), central(분석 및 ownership routing을 포함한 full-chip 회귀, JIRA 연동).

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Agent typology: regression agents make tier-level decisions; bridge agents (user–block bridge and a gate agent applying stability thresholds) mediate through an asynchronous pub-sub model on RabbitMQ; operation agents are stateless executors for dispatch (via an adapter layer and MCP interfaces), artifact collection, and ownership routing.

</div>
<div class="bi-ko" markdown>

- Agent 분류: regression agent는 계층별 판단을 담당하고, bridge agent(user–block bridge 및 안정성 임계값을 적용하는 gate agent)는 RabbitMQ 기반 비동기 pub-sub로 중개한다. Operation agent는 adapter 계층과 MCP 인터페이스를 통한 dispatch, 아티팩트 수집, ownership routing을 수행하는 stateless 실행체다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Ownership policy: the block-owner database gives the default, overridden by the most recent matching issue owner when failure similarity exceeds 90%.

</div>
<div class="bi-ko" markdown>

- Ownership 정책: 기본값은 block owner DB이며, 유사도가 90%를 넘으면 가장 최근 일치 이슈의 owner로 재할당한다.

</div>
</div>

### Results and Conclusions

<div class="bi" markdown>
<div class="bi-en" markdown>

- Evaluation covered representative blocks in an industrial SoC setting. Ablation A1 (no block agent) delayed central-regression start by about 36%; A2 (no bridge) and A3 (static scripts) are described qualitatively.

</div>
<div class="bi-ko" markdown>

- Industrial SoC 환경의 대표 block에서 평가했다. Ablation A1(block agent 제거)은 중앙 회귀 시작을 약 36% 지연시켰고, A2(bridge 제거)와 A3(정적 스크립트)은 정성적으로 기술되었다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Gated central runs started at block pass rates of 91.2% (1,343 of 1,473 passing) and 83.1% (501 passing, 102 failing), versus a traditional flow that started on largely unstable blocks.

</div>
<div class="bi-ko" markdown>

- 게이팅된 central 회귀는 block pass rate 91.2%(1,473건 중 1,343건 통과)와 83.1%(501건 통과, 102건 실패)에서 시작되었으며, 이는 대부분 불안정한 block에서 시작한 기존 흐름과 대비된다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- The authors state that large-scale quantitative evaluation is still in progress, so the claimed reductions in noise, re-run overhead, and turnaround remain unquantified beyond these examples.

</div>
<div class="bi-ko" markdown>

- 저자들은 대규모 정량 평가가 아직 진행 중이라고 밝혔으므로, 노이즈, 재실행 오버헤드, 턴어라운드 감소 효과는 위 사례 이상으로 정량화되지 않았다.

</div>
</div>
