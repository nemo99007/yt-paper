## Summary

<div class="bi" markdown>
<div class="bi-en" markdown>

**The paper presents an NXP flow that reuses C-based portable stimulus and a TLM 2.0 GP-based UVM testbench from subsystem simulation to SoC simulation, emulation, and GLS, connected through C-to-SV DPI-C.**

</div>
<div class="bi-ko" markdown>

**이 논문은 TLM 2.0 GP 기반 UVM 테스트벤치와 C 기반 portable stimulus를 DPI-C로 연결하여, subsystem 시뮬레이션부터 SoC 시뮬레이션, 에뮬레이션, GLS까지 재사용하는 NXP의 방법론을 제시한다.**

</div>
</div>

## Key Insights

<div class="bi" markdown>
<div class="bi-en" markdown>

- Wrapping subsystem UVM/SV VIPs in a C-BFM and invoking them from C through DPI-C lets the same C tests run from subsystem simulation to SoC simulation and emulation, with SoC-specific boot, clock, and reset operations handled by context mapping.

</div>
<div class="bi-ko" markdown>

- UVM/SV subsystem VIP를 C-BFM으로 감싸고 DPI-C로 C에서 호출하면, boot, clock, reset 같은 SoC 고유 동작은 context mapping으로 처리하면서 동일한 C 테스트를 subsystem 시뮬레이션부터 SoC 시뮬레이션 및 에뮬레이션까지 그대로 실행할 수 있다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- The authors report that UVM-based transactors driven through the C-BFM are at least 3x faster than executing the same stimulus through the core, based on their experiments.

</div>
<div class="bi-ko" markdown>

- 저자들의 실험에 따르면 C-BFM을 통해 구동되는 UVM 기반 transactor는 동일한 stimulus를 core로 실행하는 경우보다 최소 3배 빠르다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Building all interfaces on TLM 2.0 GP with non-blocking ports makes sequences protocol-independent, so only the driver or adapter changes when the bus protocol changes.

</div>
<div class="bi-ko" markdown>

- 모든 인터페이스를 비차단(non-blocking) 포트를 가진 TLM 2.0 GP 기반으로 구성하면 sequence가 protocol에 독립적이 되어, 버스 프로토콜이 바뀌어도 driver 또는 adapter만 수정하면 된다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Interrupt handling uses a 256-depth semaphore that locks the base application layer and raises the ISR to L1+1, and the reset env samples both implicit and explicit resets, which are reusable patterns for early driver development.

</div>
<div class="bi-ko" markdown>

- Interrupt 처리는 base application layer를 잠그고 ISR을 L1+1 계층에서 수행하는 256-depth semaphore를 사용하며, reset env는 implicit/explicit reset을 모두 샘플링한다. 이는 early driver 개발에 재사용할 수 있는 패턴이다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- GLS and emulation benefits are described only qualitatively (e.g., 'enormous', 'huge benefit') with no measured speedups, coverage, or capacity data, so the numbers should be validated before adoption.

</div>
<div class="bi-ko" markdown>

- GLS와 에뮬레이션의 이득은 'enormous', 'huge benefit' 같은 정성적 표현으로만 서술되고 실측 speedup, coverage, capacity 데이터는 없으므로, 도입 전 수치를 직접 검증해야 한다.

</div>

## Detailed Summary

### Background and Problem

<div class="bi" markdown>
<div class="bi-en" markdown>

- Rising SoC complexity and tight time-to-market make verification closure difficult, and porting tests from subsystem to SoC simulation and emulation is a recurring bottleneck.

</div>
<div class="bi-ko" markdown>

- SoC 복잡도 증가와 촉박한 time-to-market으로 verification closure가 어려워졌으며, subsystem에서 SoC 시뮬레이션과 에뮬레이션으로 테스트를 이식하는 일이 반복적인 병목이 되고 있다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Goal: reuse C-based stimulus and testbench infrastructure across subsystem simulation, SoC simulation, SoC emulation, and gate-level simulation (GLS) without rewriting.

</div>
<div class="bi-ko" markdown>

- 목표: C 기반 stimulus와 testbench 인프라를 재작성 없이 subsystem 시뮬레이션, SoC 시뮬레이션, SoC 에뮬레이션, GLS(gate-level simulation)에서 재사용하는 것이다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Reusability, protocol independence, and interoperability are targeted by building all communication on TLM 2.0 Generic Payload (TLM2-GP).

</div>
<div class="bi-ko" markdown>

- 재사용성, protocol 독립성, 상호운용성을 위해 모든 통신을 TLM 2.0 Generic Payload(TLM2-GP) 기반으로 구성하는 것을 지향한다.

</div>
</div>

### Architecture and Methodology

<div class="bi" markdown>
<div class="bi-en" markdown>

- Subsystem UVM/SV VIPs are wrapped as a C-BFM. C tests call the SV side through DPI-C; non-blocking TLM2-GP ports and trigger events synchronize each WR/RD command.

</div>
<div class="bi-ko" markdown>

- Subsystem의 UVM/SV VIP를 C-BFM으로 감싼다. C 테스트는 DPI-C를 통해 SV 측을 호출하며, 비차단(non-blocking) TLM2-GP 포트와 trigger event가 WR/RD 명령 각각을 동기화한다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- SoC-specific operations (boot, clock, reset, fault) are bound via context mapping: subsystem dummy functions map to SoC APIs. At SoC level, factory overrides switch AMBA BFMs from active to passive for protocol monitoring.

</div>
<div class="bi-ko" markdown>

- SoC 고유 동작(boot, clock, reset, fault)은 context mapping으로 연결된다. Subsystem의 dummy 함수가 SoC API에 매핑되며, SoC 레벨에서는 factory override로 AMBA BFM을 active에서 passive로 전환하여 protocol을 모니터링한다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- A reset env samples implicit and explicit resets. Interrupts use a 256-depth semaphore that locks the base layer and runs the ISR at L1+1.

</div>
<div class="bi-ko" markdown>

- Reset env는 implicit reset과 explicit reset을 모두 샘플링한다. Interrupt는 256-depth semaphore를 사용하여 base layer를 잠그고 ISR을 L1+1 계층에서 실행한다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Emulation replaces behavioral memories with vendor views and uses a TCL-driven synthesizable driver for clock and reset. Test C is compiled to hex and loaded at the boot vector. GLS compiles the netlist in parallel with the testbench and merges via a super block.

</div>
<div class="bi-ko" markdown>

- 에뮬레이션에서는 behavioral memory를 벤더 뷰로 교체하고, clock과 reset은 TCL 기반의 synthesizable driver로 생성한다. Test C는 hex로 컴파일되어 boot vector에 적재된다. GLS는 netlist를 testbench와 병렬로 컴파일한 뒤 super block으로 병합한다.

</div>
</div>

### Results and Conclusions

<div class="bi" markdown>
<div class="bi-en" markdown>

- Per the authors' experiments, UVM-based transactors driven through the C-BFM are at least 3x faster than running through the core.

</div>
<div class="bi-ko" markdown>

- 저자들의 실험에 따르면, C-BFM을 통해 구동되는 UVM 기반 transactor는 core를 통해 실행하는 방식보다 최소 3배 빠르다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- The same testbench supports native UVM sequence-based verification without a separate environment, and synthesizable slave memories eased emulation portability.

</div>
<div class="bi-ko" markdown>

- 동일한 testbench가 별도의 UVM 환경 없이 native UVM sequence 기반 검증을 지원하며, synthesizable slave memory 덕분에 에뮬레이션 이식성이 향상되었다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- GLS and emulation gains are reported only qualitatively, with no measured speedup or coverage data. The paper is primarily an experience report.

</div>
<div class="bi-ko" markdown>

- GLS와 에뮬레이션의 이득은 실측 speedup이나 coverage 데이터 없이 정성적으로만 서술되어 있으며, 본 논문은 주로 경험 보고(experience report) 성격이다.

</div>
</div>
