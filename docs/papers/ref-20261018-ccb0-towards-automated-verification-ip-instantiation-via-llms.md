## Summary

<div class="bi" markdown>
<div class="bi-en" markdown>

**An LLM pipeline (Verilog preprocessing and chunking, RAG over VIP documentation and examples, Llama-3-70b, and post-processing) automates FIFO and arbiter VIP instantiation, reaching 7/7 and 11/12 correct on small internal test sets versus 0 for the baseline.**

</div>
<div class="bi-ko" markdown>

**Verilog 전처리 및 청킹, VIP 문서·예제 기반 RAG, Llama-3-70b, 후처리로 구성된 LLM 파이프라인이 FIFO 및 arbiter VIP 인스턴스화를 자동화하며, 소규모 내부 테스트셋에서 FIFO 7/7, arbiter 11/12 정답을 달성했고 베이스라인은 0이었다.**

## Detailed Summary

### Background and Problem

<div class="bi" markdown>
<div class="bi-en" markdown>

- Verification IPs (VIPs) package reusable checkers, but deployment is slow under tight schedules and limited expertise, and LLM-generated assertions still fall short of human quality.

</div>
<div class="bi-ko" markdown>

- Verification IP(VIP)는 재사용 가능한 체커를 패키징하지만, 빠듯한 일정과 전문성 부족으로 배포가 느리고, LLM이 생성한 assertion은 여전히 사람 수준에 못 미친다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Generic LLMs lack VIP knowledge. Fine-tuning takes weeks and is costly, and limited context windows (e.g., Llama2 at 2048 tokens) truncate large RTL files.

</div>
<div class="bi-ko" markdown>

- 범용 LLM은 VIP 지식이 없다. 파인튜닝은 수 주가 걸리고 비용이 크며, 제한된 context window(예: Llama2 2048 토큰)로 대형 RTL 파일이 잘린다.

</div>
</div>

### Architecture and Methodology

<div class="bi" markdown>
<div class="bi-en" markdown>

- Four stages: (1) deterministic RTL cleaning (comments, ifdef/ifndef, and similar artifacts removed), then recursive non-overlapping partitioning under a token limit; (2) prompt augmentation with FIFO/arbiter rulesets plus either one-shot ICL or RAG retrieval from a vector DB of VIP docs and examples; (3) per-chunk LLM instantiation, with chunks pre-filtered by module naming conventions and multithreading; (4) post-processing that drops outputs with 2+ "unknown" signals and injects FIFO depth and data width extracted from source.

</div>
<div class="bi-ko" markdown>

- 4단계 구성: (1) 결정론적 RTL 정리(주석, ifdef/ifndef 등 제거) 후 토큰 상한을 따르는 중첩 없는 재귀 분할, (2) FIFO/arbiter 룰셋과 함께 one-shot ICL 또는 VIP 문서·예제 벡터 DB에서 검색한 RAG로 프롬프트 증강, (3) 청크별 LLM 인스턴스화(모듈 命名 규칙으로 청크 사전 필터링, 멀티스레딩 적용), (4) 'unknown' 신호가 2개 이상인 출력 폐기 및 소스에서 추출한 FIFO depth·data width 주입.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- RAG uses Llama3-70b-instruct. Baseline and ICL use an internal fine-tuned chipmixtral_8x7b.

</div>
<div class="bi-ko" markdown>

- RAG는 Llama3-70b-instruct를 사용한다. 베이스라인과 ICL은 내부 데이터로 파인튜닝된 chipmixtral_8x7b를 사용한다.

</div>
</div>

  B --> C[Augment: ruleset + RAG/ICL]
  C --> D[LLM instantiation]
  D --> E[Post-process: filter, fill params]

### Results and Conclusions

<div class="bi" markdown>
<div class="bi-en" markdown>

- Table I, FIFO: RAG 7/7 correct; ICL 4 correct, 1 incorrect, 2 missing; baseline 0/7 correct.

</div>
<div class="bi-ko" markdown>

- 표 I, FIFO: RAG 7/7 정답, ICL 4 정답·1 오답·2 누락, 베이스라인 0/7 정답.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Table I, arbiter: RAG 11 correct, 1 incorrect of 12; ICL 1 correct, 4 incorrect, 7 missing; baseline 0/12 correct.

</div>
<div class="bi-ko" markdown>

- 표 I, arbiter: RAG 11 정답·1 오답(총 12), ICL 1 정답·4 오답·7 누락, 베이스라인 0/12 정답.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- The authors conclude RAG gives the largest accuracy gain without fine-tuning, so newer LLMs can be swapped in.

</div>
<div class="bi-ko" markdown>

- 저자들은 RAG가 파인튜닝 없이 가장 큰 정확도 향상을 준다고 결론짓고, 더 새로운 LLM으로 교체 가능하다고 주장한다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Caveats: the sample is tiny, covers only two VIP types, and mixes different LLMs across conditions. Hallucination reduction is asserted rather than measured.

</div>
<div class="bi-ko" markdown>

- 유의점: 표본이 매우 작고 VIP 2종만 다루며, 조건별로 서로 다른 LLM을 사용한다. 환각 감소는 측정이 아니라 주장에 그친다.
