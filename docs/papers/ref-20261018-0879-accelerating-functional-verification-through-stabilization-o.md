## Summary

<div class="bi" markdown>
<div class="bi-en" markdown>

**Applying VCS Intelligent Coverage Optimization (ICO) early in GPU block verification diversifies constrained-random stimuli, exposing hidden testbench and DUT issues and cutting regressions to coverage closure, without rewriting functional coverage models.**

</div>
<div class="bi-ko" markdown>

**VCS Intelligent Coverage Optimization(ICO)을 GPU 블록 검증 초기에 적용하면 constrained-random 자극의 다양성이 높아져, 기능 커버리지 모델을 수정하지 않고도 숨은 testbench 및 DUT 이슈를 드러내고 커버리지 클로저까지의 regression 수를 줄일 수 있다.**

</div>
</div>

## Key Insights

<div class="bi" markdown>
<div class="bi-en" markdown>

- Adding ICO to a testbench already judged stable exposed about 30% more testbench and DUT issues; Figure 1 shows 360 vs 273 UVM errors over four regressions, including inconsistent-constraint failures dropping from 89 to 0.

</div>
<div class="bi-ko" markdown>

- 이미 안정적이라고 판단된 testbench에 ICO를 추가했을 때 testbench 및 DUT 이슈가 약 30% 더 드러났으며, Figure 1에서 4회 regression 동안 UVM 에러가 273건에서 360건으로 증가했고 constraint 불일치 실패는 89건에서 0건으로 줄었다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- On the L2 Cache block, 95% functional coverage was reached in 6 regressions with ICO versus 10 without (40% fewer), with no changes to functional coverage models.

</div>
<div class="bi-ko" markdown>

- L2 Cache 블록에서 ICO 사용 시 95% 기능 커버리지를 10회가 아닌 6회 regression으로 달성했으며(40% 감소), 기능 커버리지 모델은 수정하지 않았다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- On the Render Block (about 350K coverage bins), ICO shifted functional coverage closure earlier by 1.5 weeks and reduced remaining manual directed/constraint tweaking to under about 100 bins.

</div>
<div class="bi-ko" markdown>

- Render Block(약 350K 커버리지 bin)에서 ICO로 기능 커버리지 클로저가 1.5주 앞당겨졌고, 남은 수동 directed/constraint 조정은 약 100개 미만의 bin 수준으로 줄었다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Resource savings are claimed as 10-15% per block, and Figure 9 shows 198K vs 162K time units (about 18%); however, default and ICO regressions were run with different scripts (automated vs ad hoc), so the comparison is not controlled.

</div>
<div class="bi-ko" markdown>

- 자원 절감은 블록당 10-15%로 주장되며, Figure 9에서는 198K에서 162K time units(약 18%)로 나타나지만, 기본 regression과 ICO regression은 서로 다른 스크립트(자동화 대 ad hoc)로 실행되어 통제된 비교가 아니다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Before enabling ICO, a prognosis report should confirm the testbench has enough constraint freedom to diversify; tightly directed constraints limit the achievable gain.

</div>
<div class="bi-ko" markdown>

- ICO 활성화 전에 prognosis 보고서로 testbench에 다양화를 위한 constraint 자유도가 충분한지 확인해야 하며, 강하게 directed된 constraint는 얻을 수 있는 효과를 제한한다.

</div>

## Detailed Summary

### Background and Problem

<div class="bi" markdown>
<div class="bi-en" markdown>

- Constrained-random testbench tuning is manual, laborious, and risk-prone; misalignment between the implemented and intended stimulus space causes illegal/missing stimuli, over/under-bias, and bug escapes.

</div>
<div class="bi-ko" markdown>

- Constrained-random testbench 튜닝은 수작업이 많고 노력이 크며 위험이 따른다. 구현된 stimulus 공간과 의도한 stimulus 공간의 불일치로 illegal/missing 자극, over/under-bias, 버그 유출이 발생한다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Hard-to-hit (Type #2) and deep latent (Type #3) bugs surface late, when fixes are costly; GPU block verification also requires heavy manual effort for semi-directed corner-case tests.

</div>
<div class="bi-ko" markdown>

- Hard-to-hit(Type #2) 및 깊이 숨은(Type #3) 버그는 후반에 드러나 수정 비용이 크며, GPU 블록 검증은 corner case용 semi-directed 테스트 작성에 많은 수작업이 필요하다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Goal: shift-left testbench maturation using ICO in VCS, which diversifies constraint stimuli without rewriting functional coverage models.

</div>
<div class="bi-ko" markdown>

- 목표: VCS의 ICO를 활용해 constraint 자극을 다양화하고, 기능 커버리지 모델을 다시 작성하지 않은 채 testbench 성숙을 shift-left하는 것.

</div>
</div>

### Architecture and Methodology

<div class="bi" markdown>
<div class="bi-en" markdown>

- Eligibility gate: a prognosis report checks whether constraints leave enough freedom for AI/ML to bias random variables; tighter, directed constraints give less room.

</div>
<div class="bi-ko" markdown>

- 적합성 게이트: prognosis 보고서로 constraint가 AI/ML이 랜덤 변수를 편향시킬 자유도를 충분히 남기는지 확인하며, 강하게 directed된 constraint는 여지가 적다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Diversity is quantified as Shannon entropy as a percentage of the maximum; per-testbench variable randomness, value randomness, and constraint density (constraints per variable) are reported (Figures 3-4).

</div>
<div class="bi-ko" markdown>

- 다양성은 최대 가능 다양성 대비 Shannon entropy 백분율로 정량화하며, testbench별 variable randomness, value randomness, constraint density(변수당 constraint 수)를 보고한다(Figure 3-4).

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Three projects compared with/without ICO: A (L2 Cache, late stage, 10-regression baseline), B (modified L2 Cache, enabled at week 6), C (Render Block, parallel setup, about 350K bins).

</div>
<div class="bi-ko" markdown>

- ICO 사용 여부를 비교한 세 프로젝트: A(L2 Cache, 후반 단계, 10회 regression 기준), B(수정된 L2 Cache, 6주차에 활성화), C(Render Block, 병렬 구성, 약 350K bin).

</div>
</div>

### Results and Conclusions

<div class="bi" markdown>
<div class="bi-en" markdown>

- Project A: 360 vs 273 UVM errors over four regressions (Figure 1, paper states ~30% more issues); 95% functional coverage in 6 vs 10 regressions.

</div>
<div class="bi-ko" markdown>

- 프로젝트 A: 4회 regression 동안 UVM 에러 360건 대 273건(Figure 1, 논문은 약 30% 더 많은 이슈로 기술); 95% 기능 커버리지를 10회 대신 6회 regression으로 달성.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Project B: week-6 enablement yielded 18 testbench and 6 RTL bugs in that week; grid runtime 198K vs 162K time units (Figure 9); paper cites 10-15% savings.

</div>
<div class="bi-ko" markdown>

- 프로젝트 B: 6주차 활성화 시 해당 주에 testbench 버그 18건, RTL 버그 6건 발견; grid runtime 198K 대 162K time units(Figure 9); 논문은 10-15% 절감을 제시.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Project C: 1.5-week shift-left; Table 2 total bins rise from 347,984 to 349,661 (+1,677).

</div>
<div class="bi-ko" markdown>

- 프로젝트 C: 1.5주 shift-left; Table 2에서 총 bin 수가 347,984에서 349,661로 증가(+1,677).

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Caveats: self-reported, three blocks, co-authored with the ICO vendor, and default vs ICO runs used different scripting, so savings are not controlled.

</div>
<div class="bi-ko" markdown>

- 주의점: 자체 보고 결과이고 블록은 세 개뿐이며, ICO 벤더가 공저자로 참여했고, 기본 실행과 ICO 실행이 서로 다른 스크립트를 사용해 절감 효과는 통제된 비교가 아니다.

</div>
</div>
