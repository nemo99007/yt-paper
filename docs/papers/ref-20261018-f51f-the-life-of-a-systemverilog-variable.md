## Key Insights

<div class="bi" markdown>
<div class="bi-en" markdown>

- Declarations with initializers inside tasks/functions default to static in SystemVerilog, so the initializer runs only once at time 0; the paper's countones example returns 4 then 8 instead of per-call results until count is made automatic.

</div>
<div class="bi-ko" markdown>

- SystemVerilog에서 태스크/함수 내부 선언에 초기값을 주면 기본이 static이므로 초기화는 time 0에 한 번만 실행되며, 논문의 countones 예제는 automatic으로 바꾸기 전까지 호출마다 잘못된 결과(4, 이후 8)를 반환합니다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Static variables with cross-dependent initializers across packages and modules have 4P4 = 24 possible initialization orders for four variables, so use procedural assignment or construct-on-first-use instead.

</div>
<div class="bi-ko" markdown>

- 패키지와 모듈에 걸친 정적 변수의 상호 의존 초기화는 변수 4개 기준 4P4 = 24가지 초기화 순서가 가능하므로, 절차적 대입이나 construct-on-first-use 방식을 사용해야 합니다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Recursive functions require automatic lifetime: with static N, factorial(3) returns 1, while automatic yields 1 * 2 * 3 = 6.

</div>
<div class="bi-ko" markdown>

- 재귀 함수는 automatic 수명이 필요합니다. static N을 쓰면 factorial(3)이 1을 반환하지만, automatic이면 1 * 2 * 3 = 6이 됩니다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Associative arrays allocate per element and suit sparse access, while dynamic arrays are more efficient when most elements are written; queues trade fast head/tail operations for slower middle access.

</div>
<div class="bi-ko" markdown>

- 연관 배열은 원소 단위로 할당되어 희소 접근에 적합하고, 동적 배열은 대부분의 원소를 쓸 때 더 효율적입니다. 큐는 head/tail 연산에 유리하지만 중간 접근은 느립니다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Class objects are freed by reference tracking, but handles stored in static containers (e.g., a static queue) keep objects alive, so the user remains responsible for preventing memory leaks.

</div>
<div class="bi-ko" markdown>

- 클래스 객체는 참조 추적으로 해제되지만, 정적 컨테이너(예: 정적 큐)에 저장된 핸들은 객체를 살려 두므로 메모리 누수 방지는 여전히 사용자 책임입니다.

</div>
</div>

## Detailed Summary

### Background and Problem

<div class="bi" markdown>
<div class="bi-en" markdown>

- SystemVerilog variables blend hardware semantics (static, existing for the whole simulation) with software semantics (procedural, scope-bound lifetimes), and the default static lifetime is a frequent source of surprises.

</div>
<div class="bi-ko" markdown>

- SystemVerilog 변수는 하드웨어 의미론(시뮬레이션 전체 기간 존재하는 static)과 소프트웨어 의미론(절차적 코드, 스코프에 묶인 수명)을 함께 가지며, 기본 static 수명이 자주 예상 밖의 동작을 만듭니다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Recurring pitfalls: static initialization order across packages and modules, shared variables touched by concurrent `fork/join_none` threads, and object/handle lifetimes that differ from what users expect.

</div>
<div class="bi-ko" markdown>

- 반복되는 함정: 패키지와 모듈에 걸친 static 초기화 순서, 동시에 실행되는 `fork/join_none` 스레드가 공유하는 변수, 사용자의 기대와 다른 객체/핸들 수명.

</div>
</div>

### Architecture and Methodology

<div class="bi" markdown>
<div class="bi-en" markdown>

- Taxonomy of lifetimes: static (module-scope, allocated at elaboration), automatic (allocated on procedural entry, freed on exit; default in class methods, `module automatic`, and `for`-loop variables), and dynamic storage (dynamic arrays, queues, associative arrays, class objects).

</div>
<div class="bi-ko" markdown>

- 수명 분류: static(모듈 스코프, elaboration 시 할당), automatic(절차 진입 시 할당, 종료 시 해제; 클래스 메서드, `module automatic`, `for` 루프 변수의 기본값), 동적 저장소(동적 배열, 큐, 연관 배열, 클래스 객체).

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Each concept is illustrated with code (Figures 1–10) and fixes: explicit `automatic`/`static` qualifiers, splitting initialization from declaration, construct-on-first-use, and copy semantics for containers.

</div>
<div class="bi-ko" markdown>

- 각 개념을 코드 예제(Figure 1–10)와 수정 방법으로 설명: 명시적 `automatic`/`static` 지정자, 선언과 초기화 분리, construct-on-first-use, 컨테이너 복사 의미론.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- The method is a code-driven tutorial; no tooling or measurements are reported.

</div>
<div class="bi-ko" markdown>

- 코드 중심 튜토리얼 방식이며, 도구나 측정 결과는 보고되지 않습니다.

</div>
</div>

### Results and Conclusions

<div class="bi" markdown>
<div class="bi-en" markdown>

- Examples show concrete failure modes: an implicitly static `countones` gives wrong results across calls, and static `factorial(3)` returns 1 instead of 6.

</div>
<div class="bi-ko" markdown>

- 구체적 실패 사례: 암묵적 static `countones`는 호출마다 잘못된 결과를 내고, static `factorial(3)`은 6이 아닌 1을 반환합니다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Container examples track element counts (dynamic-array byte total rises from 15 to 18 after a copy), and a class example ends with 6 live object references, illustrating that users must still release handles.

</div>
<div class="bi-ko" markdown>

- 컨테이너 예제는 원소 수를 추적합니다(복사 후 동적 배열의 바이트 합이 15에서 18로 증가). 클래스 예제는 최종적으로 살아 있는 객체 참조 6개를 남겨, 핸들을 여전히 해제해야 함을 보여 줍니다.

</div>
</div>

<div class="bi" markdown>
<div class="bi-en" markdown>

- Guidance: use associative arrays for sparse access, dynamic arrays for dense writes, and explicit lifetime qualifiers to match intent.

</div>
<div class="bi-ko" markdown>

- 지침: 희소 접근에는 연관 배열, 밀집 쓰기에는 동적 배열을 사용하고, 명시적 수명 지정자로 의도를 드러내십시오.

</div>
