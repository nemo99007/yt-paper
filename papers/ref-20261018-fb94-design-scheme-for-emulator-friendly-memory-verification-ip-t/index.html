    Design scheme for Emulator-friendly Memory Verification IP to Accelerate Simulation Performance¶

    Original paper
    Authors Sunghyeon Kang (SK hynix), Munsik Bae (SK hynix), Jinsung Song (SK hynix), Minsung Kang (SK hynix), Sangkyoo Jeong (SK hynix), Seokho Hong (Siemens EDA)
    Venue DVCon US 2025
    Topic Emulation
    Type PAPER
    ID ref-20261018-fb94

    Summary¶

    Redesigns a NAND Memory VIP for co-emulation by moving UVM driver operations into a synthesizable interface with batched transfers, FSM-based control, and AC-timing FSMs, achieving about 27x faster simulation (7.38 to 204 ms/hour) on a Veloce StratoM setup.

    NAND Memory VIP를 co-emulation에 맞게 재설계해, UVM driver 동작을 합성 가능한 interface로 옮기고 batch 전송, FSM 기반 제어, AC timing FSM을 적용하여 Veloce StratoM 환경에서 약 27배 빠른 시뮬레이션(7.38 → 204 ms/hour)을 달성했다.

    Key Insights¶

    • Batching each transaction into one array transfer through the interface, instead of per-beat driver-to-DUT crossings, cuts HDL/HVL communication and raises simulation throughput from 7.38 to 204 ms/hour (about 27x).
    • 트랜잭션마다 beat 단위로 driver와 DUT 사이를 오가는 대신 interface를 통해 배열 단위로 한 번에 전송하여 HDL/HVL 통신을 줄였고, 그 결과 시뮬레이션 처리량이 7.38에서 204 ms/hour(약 27배)로 올랐다.
    • Replacing UVM #delay-based AC timing with a synthesizable AC timer FSM (timing list) and a shift-register strobe generator keeps timing inside the emulator-side logic.
    • UVM의 #delay 기반 AC timing을 합성 가능한 AC timer FSM(timing list)과 shift register 기반 strobe 생성기로 대체하여 타이밍 로직을 emulator 측에 둔다.
    • The redesigned VIP reaches about 67% of the physical NAND device board's simulation-time throughput (204 vs 304 ms/hour) and 65% of its data transfer rate (360 vs 550 KB/s), enabling pre-silicon memory-controller validation.
    • 재설계된 VIP는 물리 NAND device board 대비 시뮬레이션 시간 처리량의 약 67%(204 vs 304 ms/hour), 데이터 전송률의 65%(360 vs 550 KB/s)에 도달하여 실리콘 이전 memory controller 검증을 가능하게 한다.
    • A customized VIP is justified when vendor-specific or undisclosed NAND commands and fast-changing specs make EDA-supplied emulator VIP slow to adapt.
    • 벤더 전용 또는 비공개 NAND 명령과 빠르게 바뀌는 사양 때문에 EDA 제공 emulator VIP의 적응이 느린 경우에는 맞춤형 VIP가 정당화된다.
    • The evaluation covers a single scenario (sequential write-read on a PCIe 4.0 SSD controller, 4 channels / 4 CEs / 2 LUNs), so generality and the claimed debug-value benefits are not quantified.
    • 평가는 PCIe 4.0 SSD controller의 sequential write-read 한 가지 시나리오(4 channel / 4 CE / 2 LUN)에 국한되므로, 범용성과 주장된 디버그 가치는 정량화되지 않았다.

    Detailed Summary¶

    Background and Problem¶

    • In SoC-level UVM co-emulation, the DUT runs on the emulator while the non-synthesizable Memory VIP runs in the simulator. Frequent DUT-VIP crossings and #delay-based AC timing in drivers/monitors make the testbench the bottleneck.
    • SoC 수준 UVM co-emulation에서 DUT는 emulator에서 동작하고, 합성 불가능한 Memory VIP는 시뮬레이터에서 동작한다. 잦은 DUT-VIP 간 통신과 driver/monitor 내 #delay 기반 AC timing 때문에 testbench가 병목이 된다.
    • EDA-supplied emulator VIPs struggle to support fast-changing memory specs and vendor-specific NAND commands, which motivates a customized VIP.
    • EDA 제공 emulator VIP는 빠르게 변하는 memory 사양과 벤더 전용 NAND 명령을 지원하기 어려워 맞춤형 VIP가 필요하다.

    Architecture and Methodology¶

    • The Main Operation FSM (IDLE, WAIT, DRIVE, PAUSE, EXIT) lives in the interface. The driver calls trigger_main_fsm() and wait_end_fsm() once per transaction. Read data moves at IDLE and write data at EXIT, using arrays sized to the emulator's bandwidth.
    • Main Operation FSM(IDLE, WAIT, DRIVE, PAUSE, EXIT)은 interface에 위치한다. Driver는 트랜잭션당 trigger_main_fsm()과 wait_end_fsm()을 한 번씩 호출한다. Read 데이터는 IDLE에서, write 데이터는 EXIT에서 이동하며, 배열 크기는 emulator 대역폭에 맞춘다.
    • The AC Timer FSM (IDLE, SET, COUNT, CHECK, DONE) walks an AC timing list for one-shot parameters such as tDQSQ, tQH, and tCHZ.
    • AC Timer FSM(IDLE, SET, COUNT, CHECK, DONE)은 tDQSQ, tQH, tCHZ 같은 일회성 파라미터를 AC timing list를 따라 처리한다.
    • A shift register generates per-toggle DQS strobes for tDQSRE timing instead of an FSM.
    • tDQSRE처럼 토글마다 적용되는 DQS strobe는 FSM 대신 shift register로 생성한다.

    Results and Conclusions¶

    • Sequential write-read on a PCIe 4.0 SSD controller: simulation time rose from 7.38 ms/hour (conventional VIP) to 204 ms/hour (about 27x), versus 304 ms/hour for a physical NAND board (about 67%).
    • PCIe 4.0 SSD controller의 sequential write-read에서 시뮬레이션 시간은 기존 VIP 7.38 ms/hour에서 204 ms/hour(약 27배)로 향상되었으며, 물리 NAND board는 304 ms/hour(약 67%)이다.
    • The IO-meter data rate rose from 10 to 360 KB/s (36x), versus 550 KB/s for the board (about 65%).
    • IO meter 데이터 전송률은 10에서 360 KB/s(36배)로 올랐고, board는 550 KB/s(약 65%)이다.
    • The authors conclude the approach enables early verification before memory silicon exists. The paper reports only one scenario and does not quantify the debug benefits it cites.
    • 저자들은 이 방식이 메모리 실리콘 이전의 초기 검증을 가능하게 한다고 결론짓는다. 논문은 한 가지 시나리오만 보고하며, 인용한 디버그 이점은 정량화하지 않았다.
