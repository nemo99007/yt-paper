    Constrained-random SoC Verification Standardization SystemVerilog UVM

    DVCon › US › 2014 › Verification

    Of Camels and Committees¶

    Original paper
    Authors Tom Fitzpatrick (Mentor Graphics Corp.), Dave Rich (Mentor Graphics Corp.)
    Venue DVCon US 2014
    Topic Verification
    Type PAPER
    ID ref-20261018-2c26

    Summary¶

    A position paper arguing that SystemVerilog and UVM have reached diminishing returns and should enter a "cooling off" period, so that tool vendors can innovate on top of a stable standard core rather than facing bloated, backward-incompatible additions such as UVM 1.2 messaging and transaction-recording changes.

    SystemVerilog와 UVM이 수확 체감 단계에 도달했으므로, 도구 업체가 안정된 표준 코어 위에서 혁신할 수 있도록 "cooling off" 기간을 두어야 한다고 주장하는 입장 논문이며, UVM 1.2의 메시징 및 트랜잭션 기록 변경을 대표 사례로 든다.

    Key Insights¶

    • The proposed UVM 1.2 messaging extensions showed about a 20% performance penalty versus UVM 1.1d, and transaction-recording overhead rose from 76% (1.1d) to 126% (1.2), with the recording API changes being backward-incompatible.
    • 제안된 UVM 1.2 메시징 확장은 UVM 1.1d 대비 약 20%의 성능 저하를 보였고, 트랜잭션 기록 오버헤드는 1.1d의 76%에서 1.2의 126%로 증가했으며, 기록 API 변경은 하위 호환성이 없다.
    • Constrained-random stimulus plateaus on large SoCs: one hypothetical bus protocol already yields 4 × 2 × 16 × 100 = 12,800 transaction variants before memory-address variation is considered.
    • 대규모 SoC에서 constrained-random 자극은 한계에 부딪힌다. 가상의 버스 프로토콜 하나만으로도 메모리 주소 변형을 고려하기 전에 4 × 2 × 16 × 100 = 12,800개의 트랜잭션 변형이 존재한다.
    • Run-time phasing added in UVM 1.1 was still not fully accepted years later, and components already depend on it, illustrating the risk of releasing complex features before user vetting.
    • UVM 1.1에 추가된 run-time phasing은 수년이 지나도 완전히 수용되지 않았으며 이미 일부 컴포넌트가 이를 사용하고 있어, 사용자 검증 전에 복잡한 기능을 출시하는 것의 위험을 보여준다.
    • The authors propose a single abstract stimulus and coverage specification that can be reused both as UVM sequences and as embedded software, shifting innovation to tools layered above UVM instead of expanding its core.
    • 저자들은 UVM 시퀀스와 임베디드 소프트웨어로 모두 재사용 가능한 단일 추상 자극·커버리지 명세를 제안하며, UVM 코어를 확장하는 대신 그 위 계층의 도구에서 혁신이 일어나도록 할 것을 제시한다.

    Detailed Summary¶

    Background and Problem¶

    • SystemVerilog grew from a 140-page Verilog enhancement into a 1400-page LRM; features such as always_comb vs always @*, wildcard-index associative arrays, and program blocks are cited as overlapping or obsolete legacy.
    • SystemVerilog는 140페이지짜리 Verilog 확장에서 1400페이지 분량의 LRM으로 성장했으며, always_comb 대 always @*, wildcard 인덱스 associative array, program block 등이 중복되거나 구식이 된 사례로 거론된다.
    • UVM 1.0p1 to 1.2a grew from 288 to 351 classes and 65,534 to 75,070 lines; committee-driven "niche" features are blamed for bloat and backward incompatibility.
    • UVM 1.0p1에서 1.2a로 가면서 클래스 수는 288개에서 351개로, 라인 수는 65,534에서 75,070으로 늘었으며, 위원회 주도의 "niche" 기능이 비대화와 하위 호환성 훼손의 원인으로 지목된다.
    • SoC complexity rose from 400K gates and 1.06 processors on average (2004) to 11.1M gates and 2.25 processors (2012), exposing the limits of constrained-random stimulus and HW/SW verification.
    • SoC 복잡도는 평균 400K 게이트·프로세서 1.06개(2004년)에서 11.1M 게이트·프로세서 2.25개(2012년)로 증가했고, 이는 constrained-random 자극과 HW/SW 검증의 한계를 드러낸다.

    Architecture and Methodology¶

    • Position paper with no new tool; it reviews SystemVerilog and UVM history (OVM/VMM merger, phasing, messaging, transaction recording) and reports the authors' own overhead measurements.
    • 새로운 도구를 제시하지 않는 입장 논문으로, SystemVerilog와 UVM의 역사(OVM/VMM 통합, phasing, 메시징, 트랜잭션 기록)를 검토하고 저자들이 직접 측정한 오버헤드를 보고한다.
    • Proposes a higher-level abstract specification that generates non-repeating scenarios, reusable as UVM sequences or as software running on the processor model, with the UVM core kept stable.
    • 중복 생성을 피하는 고수준 추상 명세를 제안하며, 이 명세는 UVM 시퀀스로도, 프로세서 모델에서 실행되는 소프트웨어로도 재사용될 수 있고 UVM 코어는 안정적으로 유지된다.

    Results and Conclusions¶

    • Measured penalties on proposed UVM 1.2 code: about 20% for messaging and 65% slowdown in transaction recording (excluding file I/O); these figures are the authors' measurements, not independently reproduced.
    • 제안된 UVM 1.2 코드에서 측정된 저하: 메시징 약 20%, 트랜잭션 기록 65% 속도 저하(파일 I/O 제외). 이는 저자들의 측정치이며 독립적으로 재현되지는 않았다.
    • Cites the 2012 Wilson Research Group study: UVM usage at 41%, OVM 34%, VMM 20%, with UVM usage up 486% since 2010, used to argue that missing run-time phasing did not hinder adoption.
    • 2012년 Wilson Research Group 연구를 인용: UVM 사용률 41%, OVM 34%, VMM 20%이며, UVM 사용은 2010년 이후 486% 증가했다. 이를 근거로 run-time phasing 부재가 채택을 막지 않았다고 주장한다.
    • Conclusion: standards should be bounded and stable so that innovation happens in tools above them; further tinkering risks making UVM and SystemVerilog less effective.
    • 결론: 표준은 한정되고 안정적이어야 하며 혁신은 그 위의 도구에서 일어나야 한다. 표준을 계속 손보면 UVM과 SystemVerilog의 효율이 오히려 떨어질 위험이 있다.
