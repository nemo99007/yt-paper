    Reaching 100% Functional Coverage Using Machine Learning: A Journey of Persistent Efforts¶

    Original paper
    Authors Jaecheon Kim (Samsung Electronics), Taewook Nam (Samsung Electronics), Wonil Cho (Samsung Electronics)
    Venue DVCon US 2025
    Topic Verification
    Type PAPER
    ID ref-20261018-2c1c

    Summary¶

    A Python "coverage agent" uses decision-tree feature ranking on regression logs and coverage data to find the random variables behind unfilled cross-coverage bins, then regenerates soft-constrained tests to close cross coverage without DV engineer intervention.

    Python 기반 "coverage agent"가 회귀 로그와 커버리지 데이터에 대해 결정 트리 기반 특징 순위를 적용해 미충족 cross coverage bin의 원인 random variable을 찾고, soft constraint가 적용된 테스트를 재생성하여 DV 엔지니어 개입 없이 cross coverage를 닫는 방법을 제안합니다.

    Key Insights¶

    • Cross coverage, not individual coverpoints, is the bottleneck: in the paper's example, a non-uniform cross_test_xy (2,688 bins) reached only 99.74% after about 25,000 plain random tests.
    • Cross coverage가 개별 coverpoint가 아니라 병목입니다. 논문 예시에서 non-uniform한 cross_test_xy(2,688 bins)는 약 25,000회의 일반 랜덤 테스트 후에도 99.74%에 그쳤습니다.
    • Even uniform random weights produce highly uneven cross-bin frequencies over 5,000 runs (min 3, max 25 over 420 bins), and skewed weights such as 2:8 can prevent some bins from ever being generated.
    • 균등 random weight에서도 5,000회 실행 시 420 bins의 빈도가 최소 3, 최대 25로 크게 불균등하며, 2:8 같은 편향 weight에서는 일부 bin이 아예 생성되지 않습니다.
    • A decision tree is used as a white-box model whose feature importance identifies the variables correlated with each cross, and the number of variables is set by the cross's dimensionality.
    • 결정 트리를 white-box 모델로 사용하여 feature importance로 각 cross와 상관된 변수를 식별하며, 변수 개수는 cross의 차원 수로 정합니다.
    • Soft-constrained randomize() on predicted product sets makes wrong predictions harmless, and a candidate list of twice the required variable count gives the agent room to recover from mispredictions.
    • 예측된 product set에 대해 randomize()로 soft constraint를 적용하면 잘못된 예측도 무해해지며, 필요 변수 수의 2배인 candidate list가 오예측에서 회복할 여지를 줍니다.
    • On an industrial CSI/ISP IP (134 crosses, 14,616 bins), the agent reached 100% after 74,956 tests, whereas the baseline stayed below 70% after more than 100,000 runs; the method's benefit depends on coverpoints filling early, a condition the authors acknowledge may not hold for late-filling or non-uniform variables.
    • 산업용 CSI/ISP IP(134 crosses, 14,616 bins)에서 agent는 74,956회 테스트 후 100%에 도달한 반면, baseline은 100,000회 이상 실행 후에도 70% 미만이었습니다. 다만 저자들도 인정하듯 이 효과는 coverpoint가 일찍 채워진다는 가정에 의존합니다.

    Detailed Summary¶

    Background and Problem¶

    • Individual coverpoints fill easily under constrained-random verification, but cross coverage often leaves long tails that engineers close manually by reanalyzing reports, reweighting constraints, or adding directed tests.
    • 개별 coverpoint는 constrained-random 검증에서 쉽게 채워지지만, cross coverage는 긴 꼬리(tail)를 남기며 엔지니어가 리포트를 재분석하거나 constraint weight를 조정하거나 directed test를 추가하는 방식으로 수동 클로징해야 합니다.
    • Experiments show why repetition is inefficient: four variables (2, 6, 5, 7 values) form 420 cross bins, and under uniform weights 5,000 runs gave frequencies from 3 to 25; skewed weights (2:8, 1:9) left 3 and 20 combinations ungenerated, respectively.
    • 실험에서 반복 실행이 비효율적인 이유가 드러납니다. 4개 변수(각 2, 6, 5, 7개 값)는 420개의 cross bin을 형성하며, 균등 weight에서도 5,000회 실행 시 빈도가 3에서 25까지 분포했고, 2:8 및 1:9 편향 weight에서는 각각 3개와 20개 조합이 생성되지 않았습니다.

    Architecture and Methodology¶

    • A Python coverage agent monitors Verisium vManager regressions and merges per-test UVM logs (random-variable values), IMC coverage reports, and coverage databases into configs.csv and an overall report.
    • Python coverage agent는 Verisium vManager 회귀를 모니터링하고, 테스트별 UVM 로그(random 변수 값), IMC 커버리지 리포트, 커버리지 DB를 병합하여 configs.csv와 전체 리포트를 생성합니다.
    • A decision tree (scikit-learn) predicts each cross bin index from random-variable values; feature importance ranks the top-N variables, N being the cross's dimensionality.
    • 결정 트리(scikit-learn)가 random 변수 값으로부터 각 cross bin 인덱스를 예측하며, feature importance로 상위 N개 변수를 순위화합니다. N은 cross의 차원 수입니다.
    • Predicted variables form a product set of unseen combinations, which are emitted as soft constraints so invalid combinations fall back to normal randomization.
    • 예측된 변수들의 product set으로 아직 나오지 않은 조합을 만들고 이를 soft constraint로 발행하여, 유효하지 않은 조합은 일반 randomization으로 대체되도록 합니다.
    • Five strategies handle failure modes: fallback to random tests when predictions are too few, bin-count sanity checks, a 2x candidate list, rotation after two stagnant cycles, and de-duplication of aliased variables.
    • 실패 모드에 대응하기 위해 다섯 가지 전략을 사용합니다. 예측 변수가 부족할 때 랜덤 테스트로 대체, bin 수 검증, 2배 크기의 candidate list, 두 사이클 정체 후 조합 교체, 별칭 변수 중복 제거입니다.
    flowchart LR
  A[vManager regression] --> B[Logs, IMC reports, coverage DB]
  B --> C[configs.csv]
  C --> D[Decision tree: rank variables]
  D --> E[Product set of predicted variables]
  E --> F[Soft-constrained new suite]
  F --> A

    Results and Conclusions¶

    • Example (Figure 3 code): cross_test_xy rose from 57.66% to 94.78% in iteration 3 and reached 100% in iteration 5; 4,378 tests ran across 5 suites capped at 1,000 tests each.
    • 예시 (Figure 3 코드): cross_test_xy는 iteration 3에서 57.66%에서 94.78%로 상승했고 iteration 5에서 100%에 도달했습니다. 각 1,000개로 제한된 5개 suite에서 총 4,378개 테스트가 실행되었습니다.
    • Industrial IP (134 crosses, 14,616 bins; 21 crosses with 7,673 bins unfilled after the first regression): 100% after 74,956 tests, versus a baseline below 70% after more than 100,000 runs.
    • 산업용 IP(134 crosses, 14,616 bins; 첫 회귀 후 미충족 21 crosses, 7,673 bins): agent 적용 시 74,956회 테스트 후 100%, baseline은 100,000회 이상 실행 후에도 70% 미만이었습니다.
    • Limitations: the method assumes coverpoints fill early, and the evaluation covers only one CSI block in a mobile ISP.
    • 한계: 이 방법은 coverpoint가 일찍 채워진다고 가정하며, 평가는 모바일 ISP의 단일 CSI 블록에만 수행되었습니다.
