    Maximize Vertical Reuse, Building Module to System Verification Environments with UVM e¶

    Original paper
    Authors Horace Chan (PMC-Sierra), Brian Vandegriend (PMC-Sierra), Deepali Joshi (PMC-Sierra), Corey Goss (Cadence)
    Venue DVCon US 2013
    Topic Verification
    Type PAPER
    ID ref-20261018-7acd

    Summary¶

    The paper presents a UVM e framework that lets module testbenches be recursively imported into subsystem and system testbenches via TLM port routing, a common configuration control table, and a simplified common testflow, reportedly giving about 4x gates-verified-per-line-of-code on a 200M-gate ASIC.

    이 논문은 UVM e 기반 프레임워크를 제시한다. 이 프레임워크는 TLM 포트 라우터, 공통 설정 제어 테이블, 단순화된 공통 testflow를 통해 모듈 testbench를 서브시스템 및 시스템 testbench로 재귀적으로 import할 수 있게 하며, 200M 게이트 ASIC에서 라인당 검증 게이트 수가 약 4배 향상되었다고 보고한다.

    Key Insights¶

    • Module-to-system reuse failed in the prior 60M-gate project because lower-level code evolved without coordination, debug was slow, and knowledge did not transfer; the framework addresses this with plug-and-play module UVCs.
    • 이전 60M 게이트 프로젝트에서는 하위 레벨 코드가 조율 없이 변경되었고 디버그가 느리며 지식 전달이 되지 않아 모듈-시스템 재사용이 실패했으며, 이 프레임워크는 plug-and-play 모듈 UVC로 이 문제를 해결하고자 한다.
    • The TLM port router uses a table keyed by (port id, channel id) to support multicast and runtime rerouting, overcoming UVM's one-to-one transport binding and static analysis-port binding limits.
    • TLM 포트 라우터는 (port id, channel id)를 키로 하는 테이블을 사용해 멀티캐스트와 런타임 재라우팅을 지원하며, UVM의 1:1 transport 바인딩 및 정적 analysis port 바인딩 제약을 극복한다.
    • A common configuration control table indexed by RTL port and protocol layer lets the system UVC disable, switch to passive, or unbind internal module UVC connections without editing module code.
    • RTL 포트와 프로토콜 계층으로 색인된 공통 설정 제어 테이블을 통해 시스템 UVC는 모듈 UVC 코드를 수정하지 않고도 내부 연결을 비활성화하거나 passive로 전환하거나 바인딩을 해제할 수 있다.
    • The three testflow phase kinds (serial, parallel with sync, parallel fire-and-forget) replace the complex UVM e testflow and make module-to-system sequencing explicit.
    • 세 가지 testflow phase 종류(serial, sync를 동반한 parallel, parallel fire-and-forget)는 복잡한 UVM e testflow를 대체하며 모듈-시스템 간 시퀀싱을 명시적으로 만든다.
    • Poorly written module UVC code that is invisible at module level degraded system simulation; rewriting about a dozen lines gave a 30% performance gain, so profiling module code is essential.
    • 모듈 레벨에서는 드러나지 않는 비효율적인 모듈 UVC 코드가 시스템 시뮬레이션 성능을 저하시켰으며, 약 12줄을 다시 작성하여 30% 성능 향상을 얻었으므로 모듈 코드 프로파일링이 필수적이다.

    Detailed Summary¶

    Background and Problem¶

    • The prior project (60M gates) tried to reuse module testbench sequences, checkers, and monitors directly at system level and failed: lower-level code evolved without system impact analysis, untracked RTL changes caused wasted debug, and subsystem engineers could not support system failures. The system testbench took 2-3 months to build and was costly to maintain.
    • 이전 프로젝트(60M 게이트)에서는 모듈 testbench의 시퀀스, checker, monitor를 시스템 레벨에서 직접 재사용하려 했으나 실패했다. 하위 레벨 코드가 시스템 영향 분석 없이 변경되었고, 추적되지 않은 RTL 변경으로 디버그 시간이 낭비되었으며, 서브시스템 엔지니어가 시스템 실패를 지원하지 못했다. 시스템 testbench 구축에 2-3개월이 걸렸고 유지보수 비용도 컸다.
    • UVM provided a common architecture but lacked a plug-and-play framework for module-to-system integration. Prior literature offered theory without implementation detail.
    • UVM은 공통 아키텍처를 제공했지만 모듈-시스템 통합을 위한 plug-and-play 프레임워크는 없었다. 기존 문헌은 구현 세부 사항 없이 이론만 제시했다.

    Architecture and Methodology¶

    • A hierarchical System UVC imports module UVCs recursively (10 subsystem UVCs, depth 3). Module master sequencers are linked to the system sequencer by pointers, and stimulus layers are connected by TLM ports so the system can tap any layer.
    • 계층형 System UVC가 모듈 UVC를 재귀적으로 import한다(서브시스템 UVC 10개, 깊이 3). 모듈 master sequencer는 포인터로 시스템 sequencer에 연결되고, stimulus 계층은 TLM 포트로 연결되어 시스템이 어느 계층이든 접근할 수 있다.
    • Three enhancements to the UVM e System UVC architecture:
    • TLM port router: table-driven routing keyed by (port id, channel id), with multicast and runtime rerouting.
    • Common configuration control table: per RTL port and protocol layer, controls enable, active/passive, and TLM bind state.
    • Common testflow virtual sequence with 15 phases, each run in serial, parallel-with-sync, or parallel fire-and-forget mode.
    • UVM e System UVC 아키텍처에 대한 세 가지 개선 사항:
    • TLM 포트 라우터: (port id, channel id)를 키로 하는 테이블 기반 라우팅이며, 멀티캐스트와 런타임 재라우팅을 지원한다.
    • 공통 설정 제어 테이블: RTL 포트 및 프로토콜 계층별로 enable, active/passive, TLM bind 상태를 제어한다.
    • 15개 phase로 구성된 공통 testflow virtual sequence이며, 각 phase는 serial, sync를 동반한 parallel, parallel fire-and-forget 모드로 실행된다.
    • Module passive monitors can be enabled at system level, giving subsystem engineers the same debug view as their own testbench.
    • 모듈의 passive monitor를 시스템 레벨에서 활성화할 수 있어, 서브시스템 엔지니어가 자신의 testbench와 동일한 디버그 관점을 얻을 수 있다.

    Results and Conclusions¶

    • On the 200M-gate device, total LOC fell from 575k to 484k (-16%) and system testbench LOC from 324k to 215k (-34%). Gates verified per line rose from 104k to 413k, reported as +400%.
    • 200M 게이트 디바이스에서 전체 LOC는 575k에서 484k로(-16%), 시스템 testbench LOC는 324k에서 215k로(-34%) 감소했다. 라인당 검증 게이트 수는 104k에서 413k로 증가했으며, 보고서에는 +400%로 기재되어 있다.
    • A subsystem came up in 2-3 days, and the full system testbench was integrated in under a month. A system testcase could be written in under 20 lines.
    • 서브시스템은 2-3일 만에 가동되었고, 전체 시스템 testbench는 한 달 이내에 통합되었다. 시스템 testcase는 20줄 미만으로 작성할 수 있었다.
    • Challenges: VIP revision conflicts, poor module code (30% speedup from rewriting about a dozen lines), and difficulty porting to SystemVerilog because the testflow depends on AOP.
    • 과제: VIP 리비전 충돌, 비효율적인 모듈 코드(약 12줄 재작성으로 30% 속도 향상), testflow가 AOP에 의존하여 SystemVerilog로의 이식이 어려움.
