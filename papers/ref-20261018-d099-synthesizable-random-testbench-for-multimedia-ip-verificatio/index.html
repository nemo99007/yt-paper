    Synthesizable Random Testbench for Multimedia IP Verification¶

    Original paper
    Authors Sanggyu Park (Samsung Electronics Co., Ltd)
    Venue DVCon US 2021
    Topic Verification
    Type PAPER
    ID ref-20261018-d099

    Summary¶

    The paper proposes an isolated, synthesizable random testbench built on a custom test-program processor (TISC) and a memory-less AXI model (SynMem), so that multimedia IP tests can run identically on simulation, emulation, and FPGA at massive scale.

    이 논문은 다중 미디어 IP 검증을 위해, 전용 테스트 프로그램 프로세서(TISC)와 물리 메모리 없이 동작하는 AXI 메모리 모델(SynMem)을 기반으로 한 고립형 합성 가능(synthesizable) 랜덤 테스트벤치를 제안하여, 대규모 테스트를 시뮬레이션, 에뮬레이션, FPGA에서 동일하게 실행할 수 있게 한다.

    Key Insights¶

    • Millions of constrained-random tests for multimedia IPs with thousands of registers are infeasible in simulation, and host-driven USB/PCIe testbenches waste time on register access and cannot be reproduced in simulation.
    • 수천 개의 레지스터를 가진 다중 미디어 IP에서 수백만 건의 제약 랜덤 테스트는 시뮬레이션으로 수행하기 어렵고, 호스트가 구동하는 USB/PCIe 기반 테스트벤치는 레지스터 접근에 시간이 많이 들며 시뮬레이션에서 재현할 수 없다.
    • A custom 3-stage TISC core with 64KB program memory and APB masters compresses DUT_WRITE sequences; variable-length encoding reduces register-write test binaries to 13%-30% of fixed-length size.
    • 3단 파이프라인의 전용 TISC 코어(프로그램 메모리 64KB, APB 마스터 포함)는 DUT_WRITE 시퀀스를 압축하며, 가변 길이 인코딩으로 레지스터 쓰기 테스트 바이너리 크기를 고정 길이 대비 13%~30%로 줄인다.
    • On-chip RNGNET generates LUT data at run time: a Gamma LUT that needs at least 520 bytes as DUT_WRITE code is expressed in 27 bytes.
    • 온칩 RNGNET은 런타임에 LUT 데이터를 생성한다. 최소 520바이트가 필요한 Gamma LUT를 DUT_WRITE 코드로 표현하는 대신 27바이트로 기술할 수 있다.
    • Keeping the testbench free of external interaction (no host link, no physical SDRAM) is claimed to give bit-exact issue reproduction across simulation, emulation, and FPGA.
    • 테스트벤치를 외부 상호작용(호스트 링크, 물리 SDRAM) 없이 고립시키면 시뮬레이션, 에뮬레이션, FPGA 전반에서 이슈를 비트 단위로 동일하게 재현할 수 있다고 주장한다.
    • The paper is truncated in Section III, so SynMem implementation details and the full case-study results are not covered in this text.
    • 논문이 3장(SynMem)에서 잘려 있어 SynMem 구현 세부 사항과 전체 사례 연구 결과는 이 본문에 포함되지 않는다.

    Detailed Summary¶

    Background and Problem¶

    • Multimedia IPs (ISP, scaler, DPU) have thousands of configuration parameters; the author needed millions of random tests, which is infeasible in simulation.
    • 다중 미디어 IP(ISP, 스케일러, DPU)는 수천 개의 설정 파라미터를 가지며, 저자는 시뮬레이션으로는 불가능한 수백만 건의 랜덤 테스트가 필요했다.
    • Host-driven FPGA testbenches over USB/PCIe are slow for register access and bulk data, and their link timing cannot be reproduced in simulation.
    • 호스트가 구동하는 USB/PCIe 기반 FPGA 테스트벤치는 레지스터 접근과 대용량 데이터 전송에 시간이 많이 들고, 링크의 타이밍을 시뮬레이션에서 재현할 수 없다.
    • Embedded-CPU testbenches add C-based debugging burden that DV engineers do not want.
    • 임베디드 CPU 기반 테스트벤치는 DV 엔지니어가 원하지 않는 C 기반 디버깅 부담을 준다.

    Architecture and Methodology¶

    • TISC: a custom 3-stage pipeline core (ALU, MDU, decompression unit), 32×32-bit registers, 64KB program memory, and instructions from 8 to 80 bits. Features include a 32-flag conditional execution model, DUT_WRITE/DUT_READ pseudo-instructions with address and data compression, and 3-level CALL nesting.
    • TISC: 맞춤형 3단 파이프라인 코어(ALU, MDU, 압축 해제 유닛), 32×32비트 레지스터 32개, 프로그램 메모리 64KB, 8~80비트 명령어. 32개 플래그 기반 조건부 실행, 주소 및 데이터 압축을 적용한 DUT_WRITE/DUT_READ 의사 명령어, 3단계 CALL 중첩을 지원한다.
    • Peripherals: two APB masters (DUV and VIPs), a checksum calculator on DUV reads, programmable event I/O, timers, and random APB delay.
    • 주변 장치: DUV와 VIP용 APB 마스터 2개, DUV 읽기용 체크섬 계산기, 프로그래머블 이벤트 I/O, 타이머, 랜덤 APB 지연.
    • RNGNET: a network of 18 PRNGs with clipping, concatenation, and adders. It feeds the write data for register writes and LUT generation at run time.
    • RNGNET: 클리핑, 연결(concatenation), 가산기를 갖춘 18개의 PRNG 네트워크. 레지스터 쓰기 데이터와 LUT 생성을 위한 값을 런타임에 생성한다.
    • SynMem (AXI slave with no physical memory) is introduced but the text ends before its details.
    • SynMem(물리 메모리가 없는 AXI 슬레이브)은 소개되지만, 본문이 그 전에 끝나 세부 내용은 없다.

    Results and Conclusions¶

    • Bayer Image Processor: 9,209 registers. Test program is 90KB fixed-length, 32KB variable-length, and 13KB with run-time random generation.
    • Bayer Image Processor: 레지스터 9,209개. 테스트 프로그램은 고정 길이 90KB, 가변 길이 32KB, 런타임 랜덤 생성 시 13KB이다.
    • Image scaler: 100M tests would exceed 600GB of program data even with compression.
    • 이미지 스케일러: 1억 건의 테스트는 압축을 적용하더라도 테스트 프로그램이 600GB를 넘는다.
    • PDAF statistics (1,088 words) are checked with a single DUT_READ_RPT plus checksum.
    • PDAF 통계 정보(1,088 워드)는 DUT_READ_RPT 명령어 하나와 체크섬으로 검사한다.
    • The author reports that the custom core was preferred over a software interpreter because DV engineers can debug everything in one waveform.
    • 저자는 소프트웨어 인터프리터보다 맞춤형 코어가 선호되었다고 보고하는데, DV 엔지니어가 하나의 파형에서 모든 상태를 디버깅할 수 있기 때문이라고 설명한다.
